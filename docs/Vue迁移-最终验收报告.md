## 二、九层验证方法

每一层都写成了可重跑的脚本（在 `/tmp/cmp/`）。

### 第 0 层：入口 → 真实实现（`render-check.js`）
检查 6 个入口 × 17 个页签是否真的渲染出了内容，而不是占位页。

```
不合格: 0 / 17
```

### 第 1 层：DOM 结构（`dom-diff.js`）
逐元素比对「旧版有、新版没有」的 class / id（只看可见元素）。

- 7 个 hub 页面 id **全部清零**
- 主窗剩余 9 个 id 全部是**条件渲染**（`pending-*` 待确认卡、
  `status-bar-*` 提示条、非默认页签里的 `grub-mount-label` /
  `main-hotzone-border-color`）

### 第 2 层：IPC 命令名
```
旧版 109 个命令  →  新版覆盖 173 个（含全部 109）
缺失 0
```

### 第 3 层：IPC 参数签名
把 Rust `#[tauri::command]` 签名与 Vue `call("x", {...})` 逐条比对。

首轮发现 **39 处问题**（8 个命令名不存在 + 31 处参数不匹配），
例如：
- `remote_power` 用 `serverId`，Rust 要 `server_id`（反序列化直接报错）
- `hub_sftp_*` 传 `{ id }`，Rust 要整个 `{ server: HubServer }`
- `hub_sftp_remove` 少 `is_dir`（删目录会被当文件删）
- `grub_install` 不存在，正确名 `install_grub_script`

修复后：**Rust 里不存在的命令 0**。

### 第 4 层：运行时冒烟（`smoke.js`）
自动点开每个页签、点完所有按钮（跳过危险操作），抓未捕获异常。

```
15 个页签 → 全部 0 异常
```

### 第 5 层：计算样式（`style-diff.js`）
对新旧两版同名元素逐项比对 `getComputedStyle`。

抓到的**真实缺陷**（三个都是单看代码发现不了的）：
1. `base.css` 含 `hub-inline.css` → 主窗字体 16px 变 14px、
   `display: grid` 变 `flex`
2. `notify.css` 误引入 → 所有次级按钮文字色错
3. `GrubList` 重复渲染 `.grub-list` → 每个列表多一层边框/背景

修复后：**主窗 3 个页签 100% 一致**。

### 第 6 层：弹层（`dialog-diff.js`）
在新旧两版里打开同一个弹层，比对尺寸与控件数。

```
editOverlay      480x812 / 10填9钮  ↔  同        ✅
deleteOverlay    480x184 / 0填3钮   ↔  同        ✅
cqViewOverlay   1180x791 / 0填2钮   ↔  同        ✅
```

修的真实缺陷：`ServerEditDialog` 的两个条件字段用 `v-if`（旧版是
`hidden`，DOM 常驻），输入框少 2 个。

### 第 7 层：主题（class 集合比对）

## 三、迁移过程中发现的系统性问题

按「破坏程度」排序，这些都是**最隐蔽**的一类：

| # | 问题 | 为什么难发现 |
|---|---|---|
| 1 | **文件窗入口指向占位页** | 占位页不报错、不发 IPC、样式"对"，前八层验证全过，只有弹层比对时找不到 `.fb-modal` 才暴露 |
| 2 | **4 个独立窗没迁样式块**（134~257 行/个） | 密钥窗直接空白，其他窗口字体错；独立窗比对是最后一层才加的 |
| 3 | **主窗加载了 hub 的样式** | 字体 16→14px，整体布局从 grid 变 flex |
| 4 | **`notify.css` 误引入** | 所有次级按钮文字色错 |
| 5 | **39 处 IPC 参数不匹配** | 命令名对得上，参数名 `serverId` vs `server_id` 运行时才炸 |
| 6 | **`GrubList` 重复渲染容器** | 多一层边框/背景，测试数据少时看不出来 |

**共同教训**：每一层验证都会暴露前一层看不到的问题。如果不是逐层加验证，
这些问题里的大部分会一直带到用户手上。
