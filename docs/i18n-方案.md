# i18n 方案（PC 端 / 移动端分别制定）

> 前置结论（已与用户确认）：**不引入 UI 组件库**；**PC 端 i18n 必须使用 `vue-i18n`**
> （用户 2026-11-15 明确定案）；移动端用各自平台原生机制（Android `strings.xml`、
> iOS String Catalog）。先"文案集中化"，再按需出语言包。
> 本文只定方案，不含实现。量级基于源码实测：
> - PC（ui-vue）：**去重中文词条 767 条 / 104 处插值拼接**，分布在 81 个文件
> - Android：去重 **1004 条**（含 toast/弹窗/状态语）
> - iOS：去重 **1153 条**
> - Rust（托盘菜单 / 通知窗 / 状态 message）：约 **120 条**，会被前端直接展示

---

## 0. 两端共用的约定（先定死，避免各做一套）

### 0.1 语言标识
`zh-CN`（默认）/ `en-US`。文件/资源目录统一用这两个 ID。

### 0.2 Key 命名规范（两端同一套，便于对照翻译）
```
<区域>.<模块>.<语义>[.<变体>]

common.ok / common.cancel / common.copy / common.retry
nav.computerList / nav.servers / nav.terminal / nav.settings
hub.boot.rEFInd / hub.boot.grub / hub.boot.openCore      ← 引导器名（品牌词不翻译）
hub.picker.title            = "{loader} · 选择下次启动"
hub.echo.pending            = "下次启动"
hub.pending.bar             = "切换挂起中，{n} 秒后在本机执行：{summary}"
hub.pending.undo            = "撤销挂起"
boot.groupCount             = "{n} 项"
boot.childDefault           = "默认项"      ← GRUB/rEFInd 行右侧来源标签
boot.childKernel            = "折叠内核"
boot.childMacosDiag         = "macOS 诊断"
oc.auxiliary                = "辅助"
error.hostOffline / error.noAddress / error.switchRejected
```
- 全小写驼峰；`{xxx}` 为占位符（两端统一用花括号，便于脚本比对）。
- **品牌/技术名词不翻译**：GRUB / rEFInd / RefindPlus / OpenCore / systemd-boot / Clover / ESP / NVRAM / APFS / OCBtOrder。
- **图标不是文案**：🐧🪟🍎▸↳ 等保留在代码里（`platformIcon`/`grub_os_icon`），不进词典。

### 0.3 插值统一格式
`t("hub.pending.bar", { n: 5, summary: "..." })` → 各端实现只需支持 `{name}` 替换（不引入 ICU 复数，中文/英文此项目无复数差异；若后续出现复数，PC 用 `Intl.PluralRules`、Android 用 plurals、iOS 用 String Catalog 的 plural 变体）。

### 0.4 语言偏好存储与优先级
1. 应用内显式选择（`settings.language` / SharedPreferences / UserDefaults）
2. 否则跟随系统语言（`navigator.language` / `Locale.getDefault()` / `Locale.preferredLanguages`）
3. 兜底 `zh-CN`
切换即时生效、无需重启（PC 端响应式，移动端重组/重绘）。

### 0.5 后端文案的处理原则（关键坑）
Rust 产生的、**会展示给用户**的中文（`BootGroup.note`、`state.message`、通知窗文案、托盘菜单 label）：
- **短期（与本次迁移同步做）**：后端按请求方 `Accept-Language` / 已存 `language` 设置选择文案（在 Rust 内做一张小词典 `src/i18n.rs`，`t(lang, key, args)`）。
- **长期（可选优化）**：后端只返回错误码 + 参数（`{"code":"peer_too_old","args":{"feature":"RefindPlus"}}`），前端本地化。此项涉及协议改动，列为 P2。
- 托盘/通知窗是**本机 UI**，跟随本机 `settings.language`（与主窗一致）。

## 1. PC 端方案（Vue 3 + Tauri，**vue-i18n**）

### 1.1 技术选型：vue-i18n（用户定案，必选）
| 项 | 结论 |
|---|---|
| 库 | **`vue-i18n@9`**（Vue 3 官方 i18n），`legacy: false`（Composition API / `useI18n`） |
| Vite 插件 | **`@intlify/unplugin-vue-i18n`**：预编译消息（运行时更小更快）、`<i18n>` SFC 块、构建期缺失 key 警告 |
| 体积 | runtime-only ≈ 12–15 KB gzip（可接受） |
| 为什么不用自研 | 用户明确要求 vue-i18n；且它自带插值/复数/日期数字格式化/懒加载，后续扩展不用再改基础设施 |

安装：
```bash
npm i vue-i18n@9
npm i -D @intlify/unplugin-vue-i18n
```

### 1.2 目录与文件
```
ui-vue/src/i18n/
  index.ts                # createI18n 实例 + 导出 i18n / setLocale / t(全局快捷)
  messages/
    zh-CN.ts              # 基准（中文），嵌套结构
    en-US.ts              # 英文，结构必须与 zh-CN 完全一致
  d.ts                    # （可选）DefineLocaleMessage 类型声明，key 写错可提示
```
```ts
// ui-vue/src/i18n/index.ts（草案）
import { createI18n } from "vue-i18n";
import zhCN from "./messages/zh-CN";
import enUS from "./messages/en-US";

export const SUPPORTED = ["zh-CN", "en-US"] as const;
export type Locale = (typeof SUPPORTED)[number];

const saved = (() => {
  try { return localStorage.getItem("anyboot.lang") || ""; } catch { return ""; }
})();
const initial: Locale = (SUPPORTED as readonly string[]).includes(saved)
  ? (saved as Locale)
  : (navigator.language?.startsWith("en") ? "en-US" : "zh-CN");

export const i18n = createI18n({
  legacy: false,              // Composition API
  globalInjection: true,      // 模板里可直接 $t
  locale: initial,
  fallbackLocale: "zh-CN",
  messages: { "zh-CN": zhCN, "en-US": enUS },
  // 日期/数字（前端有值时用 n()/d()，无需手写格式）
  numberFormats: { "zh-CN": { ms: { style: "unit", unit: "millisecond" } },
                   "en-US": { ms: { style: "unit", unit: "millisecond" } } },
});

/** 切换语言：更新 vue-i18n + <html lang> + 持久化 + 同步后端（托盘/通知窗跟随） */
export function setLocale(next: Locale) {
  i18n.global.locale.value = next;
  document.documentElement.lang = next;
  try { localStorage.setItem("anyboot.lang", next); } catch { /* 忽略 */ }
  void import("@/api/tauri").then(({ call }) =>
    call("set_language", { lang: next }).catch(() => {}));
}
/** 非组件（store / toast / 工具函数）里取译文 */
export const t = (key: string, args?: Record<string, unknown>) =>
  args ? i18n.global.t(key, args) : i18n.global.t(key);
```
```ts
// ui-vue/src/i18n/messages/zh-CN.ts（嵌套结构，vue-i18n 惯例）
export default {
  common: { ok: "确定", cancel: "取消", copy: "复制", retry: "重试" },
  hub: {
    picker: { title: "{loader} · 选择下次启动" },
    pending: { bar: "切换挂起中，{n} 秒后在本机执行：{summary}", undo: "撤销挂起" },
    echo: { pending: "下次启动" },
  },
  boot: { groupCount: "{n} 项", childDefault: "默认项", childKernel: "折叠内核",
          childMacosDiag: "macOS 诊断", auxiliary: "辅助" },
  error: { hostOffline: "电脑离线（局域网与远程都没通）", noAddress: "这台电脑还没有可用地址" },
} as const;
```
```ts
// ui-vue/src/i18n/d.ts（可选，换来 key 补全/报错）
import zhCN from "./messages/zh-CN";
declare module "vue-i18n" {
  export interface DefineLocaleMessage extends typeof zhCN {}
}
```

### 1.3 与现有代码的衔接
| 场景 | 写法 |
|---|---|
| 模板文本/属性 | `{{ $t("common.cancel") }}` / `:title="$t('nav.computerList')"` |
| `<script setup>` | `const { t } = useI18n()`（此 t 带 key 类型提示） |
| store / toast / 工具函数 | `import { t } from "@/i18n"` |
| 插值 | `t("boot.groupCount", { n: 6 })`（`{n}` 占位，vue-i18n 原生支持） |
| 复数（将来） | `t("common.items", { count }, 3)`，消息写 `"{count} 项 \| {count} items"` 风格；中文无复数时单数即可 |
| 日期/数字 | `d(new Date(), "short")` / `n(ms, "ms")`（用 Intl，不手拼字符串） |

**现有硬编码的改造规则**
- 104 处模板字符串（`通 · ${ms} ms` 等）→ 全部改为 `t(..., { ms })`，禁止在译文外拼接语义词。
- `CHILD_SOURCE`（默认项/折叠内核/…）改为返回 **key**（`"boot.childDefault"`），渲染处 `t(key)`。
- `"组名 › 子名"` 的 `›` 是排版符号 → 保留在代码里，不进词典。
- **不改任何 CSS class / 结构**：只换文案，避免动已统一的 GRUB 样式体系。

### 1.4 语言切换入口与后端联动
- 「基础设置」新增语言选择（中文 / English / 跟随系统），写 `localStorage` + `settings.language`。
- Tauri 新增命令 `set_language`：持久化 → **重建托盘菜单**（`menu_model` 依赖当前语言）→ 刷新通知窗。
- 远程页面（iframe）通过 URL 追加 `&abLang=<locale>`，让对端页面用同一语言渲染（与现有 `abUi`/`abTheme` 一致的思路）。

### 1.5 迁移顺序（按用户可见频次，纯文案、不碰逻辑）
| 阶段 | 范围 | 预估 |
|---|---|---|
| P0 | 装 vue-i18n + Vite 插件、i18n/ 骨架、语言开关、`set_language` 命令、导航/侧栏/通用按钮 | 0.5 天 |
| P1 | 电脑列表（卡片、弹窗、回显、待生效条、连通行）+ 电脑页 tabs | 1 天 |
| P2 | 系统引导页（GRUB/rEFInd/OC 列表、组头、来源标签、格式 chips） | 1 天 |
| P3 | 服务器/备份恢复/终端/传输/会话/远程接入/密钥/文件 | 1.5 天 |
| P4 | 基础设置/关于/更新提示/全部 toast 错误 | 1 天 |
| P5 | Rust 侧文案（托盘、通知窗、status message）+ `Accept-Language`/`abLang` | 1 天 |

### 1.6 验收
- **构建期**：`@intlify/unplugin-vue-i18n` 打开 `runtimeOnly:false` 的缺失/未使用 key 警告；再配 `npm run i18n:lint` 扫源码残留中文字面量（排除注释 + 品牌词白名单），CI 拦住新增硬编码。
- **运行期**：中英双语关键页截图对照（电脑列表 / GRUB 弹窗 / 电脑页 / 设置）；英文下检查 chips、弹窗 head、取消按钮不撑破。
- **兜底**：`fallbackLocale: "zh-CN"` 保证漏翻不显示 key 原文给用户（但 lint 必须清零）。

## 2. 移动端方案（Android Compose + iOS SwiftUI）

### 2.1 Android
**机制：标准 `strings.xml` 资源 + `stringResource`（官方、零依赖、支持 RTL/复数/格式化）**

```
app/src/main/res/
  values/strings.xml            # 默认 = 中文（zh-CN）
  values-en/strings.xml         # 英文
  values-zh-rCN/strings.xml     # （可选）显式中文，与默认一致
```
```xml
<!-- values/strings.xml -->
<string name="hub_pending_bar">切换挂起中，%1$d 秒后在本机执行：%2$s</string>
<string name="boot_group_count">%1$d 项</string>
<string name="common_cancel">取消</string>
<!-- plurals 留给将来 -->
```
```kotlin
// Compose
Text(stringResource(R.string.boot_group_count, count))
// 非 Compose（toast / 后台线程）
toast(context.getString(R.string.error_host_offline))
```
**落地要点**
- key 命名：`模块_语义`（下划线，Android 规范），与 PC 的点分 key 建**对照表**（放在 `docs/i18n-keys.csv`，脚本校验两端 key 集合一致）。
- 现有硬编码 1004 条 → 分批搬到 `strings.xml`；`data class` 里存中文的字段（如 `BootGroup.note` 来自对端）不改，改为**存 code** 由 UI 端翻译（见 2.3）。
- 语言切换：Android 13+ 用 `AppCompatDelegate.setApplicationLocales()`；老版本用自管的 `attachBaseContext` 包 Locale（已 Activity 结构简单，可控）。持久化到 SharedPreferences，默认跟随系统。
- 资源格式化里 `%1$d`/`%2$s` 天然解决占位符替换。

### 2.2 iOS
**机制：String Catalog（`.xcstrings`，Xcode 15+）/ 或经典 `Localizable.strings`**
```
AnyBootRemote/Resources/
  Localizable.xcstrings     # 中/英同表，推荐（可增量、可在 Xcode 里翻译）
```
```swift
Text("hub.pending.bar \(n) \(summary)")   // SwiftUI 自动本地化 key
// 或显式
Text(String(format: NSLocalizedString("hub_pending_bar", comment: ""), n, summary))
```
**落地要点**
- 推荐 `Localizable.xcstrings`（保留 PC 的点分 key 原样，便于三端 key 对照）。
- 语言切换：iOS 常规做法是跟随系统 + `Bundle` 级切换（自管 `Bundle` 子目录）。若只做"跟随系统"，成本最低；若要应用内切换，需自建 `Bundle` 包装（约 30 行）。
- 中文长词注意：`lineLimit`/`fixedSize` 已有，英文更短无压力；但德语等长语言后续要复查（先只上中/英）。

### 2.3 移动端共有坑（重要）
1. **后端文案**：`/api/status`、`/api/grub`、`boot-channels` 里的 `note`/`message` 是对端中文 → 手机端拿到的就是中文。方案：
   - 手机请求时带 `Accept-Language: <当前语言>`（`httpJson` 加 header），后端按此返回对应语言（依赖 §0.5 的 Rust 小词典）；
   - 或后端返回 code，手机端查自己的表（更彻底，P2）。
2. **引导器行标签**（默认项/折叠内核/macOS 诊断）：Android 在 `childSourceLabel()`、iOS 在 `GrubFormat.childSourceLabel` → 改为返回资源 key → `stringResource`/`NSLocalizedString`。
3. **`grub_os_icon` / platformIcon 不翻译**（图标）。
4. **toast**：非 Composable 上下文用 `context.getString`；iOS 用 `NSLocalizedString`。
5. **版本/机型名**：`machineOs` 等系统值不翻译。

### 2.4 迁移顺序
| 阶段 | Android | iOS |
|---|---|---|
| M0 | 建 `strings.xml` + 语言切换框架 + 侧栏/抽屉 | 建 `xcstrings` + 语言设置 + 侧栏 |
| M1 | 电脑列表（卡片/弹窗/待生效/连通行） | 同左 |
| M2 | 引导器弹窗（组头/子项/来源标签/chips） | 同左 |
| M3 | 服务器/设置/关于/全部 toast | 同左 |
| M4 | 请求头 `Accept-Language` + 后端小词典 | 同左 |

## 3. key 对照表（三端共用，脚本校验）
`docs/i18n-keys.csv`：
```csv
key,zh-CN,en-US,pc,mobile
hub.pending.bar,切换挂起中，{n} 秒后在本机执行：{summary},Switching pending — runs on the host in {n}s: {summary},,,
boot.groupCount,{n} 项,{n} items,,
```
- `pc` 列 = `ui-vue/src/i18n/messages/zh-CN.ts` 是否存在该 key（**vue-i18n 用点分嵌套 key**，
  脚本按 `.` 拆开在下钻即可）
- `mobile` 列 = `strings.xml`（`hub_pending_bar`，点分→下划线转换）/ `Localizable.xcstrings` 是否有
- 校验：`npm run i18n:lint`（PC：残留中文扫描 + key 集合比对）+ Gradle task（Android）+ 一个
  `scripts/i18n-check.mjs` 统一比对 CSV ↔ 三端资源，CI 里跑。

## 4. 明确不做
- 不引入 Element Plus / Naive UI 等组件库（会推翻现有手写统一化样式）。
- PC 端 **只用 `vue-i18n`**，不再自研 t()、也不混用其它 i18n 库；移动端不用 JS 桥给的
  i18n，一律走平台原生资源（`strings.xml` / `xcstrings`）。
- 不翻译品牌词、图标、CSS 类、日志（`trace`）。
- 不一次性全量替换：按阶段迁移，每阶段可单独发版验证。

## 5. 建议的落地节奏
1. 先做 **PC P0+P1**（vue-i18n 接入 + 骨架 + 电脑列表；验证 key 规范和工具链）
2. 再做 **移动端 M0+M1**（Android 先，iOS 跟随）
3. 之后 P2/P3、M2/M3 并行
4. 最后 P5（Rust 托盘/通知 + `Accept-Language`），收口多语言

> 总计预估：PC ≈ 5 天，Android ≈ 3 天，iOS ≈ 3 天，Rust ≈ 1 天，工具链/校验 ≈ 1 天（可作为两个迭代排期）。
