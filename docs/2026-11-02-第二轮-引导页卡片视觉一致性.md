## 背景

用户在 J 布局下逐一指出三个通道（rEFInd / GRUB / OpenCore·systemd-boot·Clover）
的卡片外观**处处不统一**：多出阴影块、多出空行、宽度不一致、滚动条位置不同、
面板框套娃、上下左右留白参差。

每一条都是**先用 headless Chrome + CDP 实测**（读 `getBoundingClientRect` /
`getComputedStyle` / `scrollWidth`），定位到具体元素与具体像素值后再改。

---

## 逐条问题与根因

### ① OpenCore 区域多出一块灰底「阴影块」
三张卡片外层**完全一致**（白底 / 1px 边框 / 10px 圆角 / 无阴影），差别在
OpenCore 内部多包了一层 `.oc-menu`：

```
.oc-menu  bg=color(srgb …/0.03)  padding=10px 12px  radius=10px
```

3% 浅灰 + 内边距 + 圆角，在白卡里显出一块略小的灰底。
**修**：去掉 `background` / `padding` / `border-radius`，只留 `margin-bottom`。

### ② GRUB 顶部比 rEFInd 多一个空行
主题态下 `.grub-head` 的标题行与状态小字都被隐藏，**高度变成 0**，
但它是 `display:grid` 的 section 子项 —— **0 高元素仍然参与 `gap: 10px`**：

```
refind  section 顶 192 → grub-panel top=192   （紧贴）
grub    section 顶 752 → .grub-head h=0 → grub-panel top=762   ← 多 10px
```

**修**：`.ba-theme-sec > .grub-head { display: none }`。

### ③ GRUB 列表比另两个窄 2px
`.grub-auto-card` 有 `border: 1px` + `input-bg` 底色，等于「卡里套卡」，
把内层 `.grub-list` 挤窄 2px 并显出一块多余底色。
**修**：主题态下去掉它的边框与底色。

### ④ 三个通道的面板容器根本不是同一个
```
rEFInd    grub-panel(822) → sim-scan → sim-scan-list → .grub-list.sim-list(811)
GRUB      grub-panel(822) → grub-auto → grub-auto-card(822)     ← 无边框无底色
OpenCore  oc-menu(822) → .grub-list.grub-list-body(822)
```
三处不一致：容器不同、宽度差 11px、滚动层数不同（2 / 1 / 0）。
**修**：统一「面板框」样式；去掉 `.sim-scan-list` 的中间滚动层（一个面板只留一层滚动框）。

### ⑤ 滚动条离右边的距离不一样
```
rEFInd    right=1061  gapToRight=0   滚动条 13px
OpenCore  right=1072  gapToRight=0   滚动条 13px
GRUB      right=1056  gapToRight=16  滚动条 11px
```
GRUB 内层比父容器窄 21px（`grub-auto-card` 的 padding 4 + border 1 叠加内层 padding）。
**修**：内层 `width/max-width: 100% !important`；去掉 `grub-auto-card` 的 padding/border；
一层面板只留一层滚动框。

### ⑥ 包住列表的「面板框」不想要
面板框在通道卡片里又画了一个内缩小框，**左右上下各吃掉 5px**。
**修**：三个通道全部 `background: transparent; border: 0; padding: 0`。
收益：一屏多显示 1~2 条，滚动条贴边。

### ⑦ 滚动条后面还有 17px 空隙
列表 `right=1072`，卡片 `right=1089` —— 卡片 `padding-right: 16px` + 1px 边框。
**修**：`.ba-theme-sec { padding-right: 0 }`，列表 `margin-right: 0; width: 100%`。

### ⑧ 左侧也要撑满
左侧同样 17px（`padding-left: 16px` + 边框）。
**修**：`.ba-theme-sec { padding-left: 0 }`，左右对称收掉。

### ⑨ OpenCore 缺少顶部 4px 间隙
```
rEFInd    面板顶→列表顶 4px（.grub-panel padding-top: 4px）
GRUB      4px
OpenCore  0     ← 列表挂在 .oc-menu 上，那层 padding 早前被清零
```
**修**：`.oc-menu { padding-top: 4px }`（其余三边保持 0）。

## 顺带修掉的隐性问题

**置顶行到列表顶的距离：rEFInd 4px / GRUB 0 / OpenCore 0**

排查花了三轮：
1. 先怀疑 `.grub-list { padding: 4px }` → 归零后**仍是 4px**
2. 再查 DOM：rEFInd 的置顶行不是列表首个子元素，而是带 `is-group` 的项
3. 真正原因：`.grub-entry.is-group { margin-top: 4px }`（给组头预留的上边距），
   GRUB / OpenCore 的置顶行是 `is-child`，没有这个 margin

**修**：`.grub-list > .grub-entry:first-child { margin-top: 0 }`
（列表首项上面没有内容可分隔，这 4px 是纯留白；非首项的 4px 保留，它确实起分组作用）

## 最终实测（J 布局，1400 宽，三通道逐个点开）

| 通道 | 左缘空隙 | 右缘空隙 | 顶部间隙 | 置顶距列表顶 |
|---|---|---|---|---|
| rEFInd | 1px | 1px | 4px | 0 |
| GRUB | 1px | 1px | 4px | 0 |
| OpenCore | 1px | 1px | 4px | 0 |

（左/右那 1px 是卡片自身的边框；systemd-boot / Clover 与 OpenCore 同路径，自动一致）

## 方法记录

这一轮全部靠 **headless Chrome + CDP 实测**定位，没有一次靠读代码猜：

```js
// 取真实盒模型
el.getBoundingClientRect()   // left/top/right/width/height
el.clientWidth               // 内容宽（可看出滚动条占位）
getComputedStyle(el).padding / border / margin / overflowY
```

被实测纠正过的三次错误假设：
- 「宽度不一致」→ 卡片其实同宽 340，差在内层列表
- 「顶部 4px 是 padding」→ 归零后没变，真因是 `is-group` 的 margin
- 「滚动条位置不同」→ 真因是内层被 `auto-card` 的 padding+border 挤进去 21px
