# 多实例扫描性能复核与优化方案

> 2026-11-21。多实例模型（0.2.13+）落地后对「扫描/视构建」链路的复核与优化方案。
> **前身**：`2026-11-07-引导器扫描性能优化方案-废弃.md`（单实例时期的 T1–T8，已废弃但保留存档；
> 其 T1–T8 的扫描优化在当前代码中**仍然生效并被复用**，本文只复核「新增的实例视图链路」）。
> 相关代码：`src-tauri/src/instances.rs`、`remote_servers.rs`（`all_channels_json` / `instance_boot_groups`）、
> `channels/opencore.rs`（`view`）、`channels/oc_menu.rs`（`preview` / `order_match`）、`channels/refind_menu.rs`。

## 1. 实测（本机 Linux，5 个实例）

> 触发：用户报「选中延迟」+「GRUB 页签消失」。逐段实测（`ANYBOOT_TRACE=1`，新增
> `inst.build[...]` / `instances.all` / `inst.*` 埋点）后确认：**T1–T8 的扫描优化都被
> 多实例路径正常复用了，慢的是「实例视图构建」这条新链路没有任何缓存。**

### 1.1 明细

| 环节 | 实测 | 说明 |
|---|---|---|
| `linux_grub_switch`（写 grubenv） | **40 ms** | T1–T3 生效 |
| `remote_boot_switch`（实例分支） | **78 ms** | |
| `inst.build[grub@EFI]` | **0 ms** | 走 `remote_grub_json`（复用 linuxGrub 快照） |
| `inst.build[opencore@EFI/OC]` | **443–451 ms** ×2 | `opencore::view` → `oc_menu::preview` 每次重解析 `config.plist` |
| `inst.build[refind@EFI/BOOT]` | **333–347 ms** | 大头是卷标解析 `cmd.lsblk_label`（refresh 里 18 次≈719 ms） |
| `inst.build[refindplus@EFI/BOOT]` | **329–335 ms** | 同上 |

| `remote_boot_info(local)` | 1.5 s | 被上者拖 |
| `remote_boot_info(PC)` | 6–7.6 s | 探活（多地址超时）+ 对端同样 1.5 s 的 boot-channels |

## 2. 旧优化项在多实例路径的复用情况

| 优化项 | 复用？ | 依据 |
|---|---|---|
| T1 A1/A2/A3（scan_ext4 短路 / 按需 stat / 块缓存） | ✅ | grub 实例 0 ms |
| T2 D1（已挂载直读） | ✅ | `scan_instances`/ESP 读取走挂载点 |
| T3 A4（分区并行） | ✅ | `probe_raw` 并行 |
| T4 B1/B2（macOS list -plist + 类型预筛） | ✅ | `scan_instances` 复用 |
| T5 E1（启动 grub ‖ channels 并行） | ✅ | refresh 合计 984/1059 ms 两段并行 |
| T6 E3（OC order_match 合并映射 + 10 s TTL） | ⚠️ 部分 | `oc.order_match` 已 90 ms，但 `oc_menu::preview` 整体仍每次重解析 plist（`oc.volumes` 349 ms / `oc.build_order_items` 153 ms） |
| T7 E2（分区级指纹磁盘缓存） | ⚠️ 部分 | `linux_probe_cache` 只覆盖 GRUB 全盘探测；**实例视图（refind 预演 / oc 预演）完全没有指纹缓存** |
| T8 E4（重新读取 6 次 → 1 次） | ✅ | 前端 `refreshAuto` 单次 |

## 3. 优化方案（按收益/风险排序）

| # | 方案 | 预期 | 风险控制 |
|---|---|---|---|
| P1 | **实例视图按文件指纹缓存**：key=instanceId，指纹 = `config.plist`/`grub.cfg`/`vars/`（PreviousBoot 等）/`refind_linux.conf` 的 mtime+size + 分区键；命中直接回上次 `BootGroup` | 1.55 s → **~30–60 ms** | 只缓存**成功且完整**的结果；切换成功后就地改该条 `current`，不做全量失效 |
| P2 | **卷标解析缓存**：`cmd.lsblk_label` 按设备缓存，分区表变更失效 | refind/refindplus 335 → ~30 ms | 指纹失效；不做短 TTL 盲缓存 |
| P3 | **opencore 视图缓存**：plist 文本按 mtime 缓存 + `oc.volumes`/`oc.build_order_items` 按「mtime + 卷列表」缓存 | 443 → ~50–80 ms | 写 OCBtOrder/bless 后显式失效（已有 T6 映射） |
| P4 | `/api/boot-channels` 合并结果缓存（5 s 防抖） | 连续请求近 0 | **实例数变少视为部分结果，不写缓存**（2026-11-21 踩过：扫描不全缓存 3 条 + 前端剪 order → 页签永久消失） |
| P5 | 远端刷新：`remote_boot_info` 3–5 s 缓存 + 探活结果 10 s 复用；切换后本地回显（已落地） | PC 行 7.6 s → ~1 s（对端升级后） | 探活失败不缓存 |
| P6 | 启动时后台预构建实例组（首屏不等） | 首次进页面秒开 | 构建完成再推 UI |

> 配套已修：`bootInstances.setInstances()` 从「按当次结果剪 `instanceOrder`」改为**只补不删**，
> 扫描不全不再丢页签（`grub`/`refindplus` 曾因此消失）。
