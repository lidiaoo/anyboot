# 多实例扫描性能复核与优化方案

> 2026-11-21。多实例模型（0.2.13+）落地后对「扫描/视图构建」链路的复核与优化方案。
> **前身**：`2026-11-07-引导器扫描性能优化方案-废弃.md`（单实例时期的 T1–T8，已废弃但保留存档；
> 其 T1–T8 的扫描优化在当前代码中**仍然生效并被复用**，本文只复核「新增的实例视图链路」）。
> 相关代码：`src-tauri/src/instances.rs`、`remote_servers.rs`（`all_channels_json` / `instance_boot_groups`）、
> `channels/opencore.rs`（`view`）、`channels/oc_menu.rs`（`preview` / `order_match`）、`channels/refind_menu.rs`。

## 1. 实测（本机 Linux，5 个实例）

> 触发：用户报「选中延迟」+「GRUB 页签消失」。逐段实测（`ANYBOOT_TRACE=1`，新增
> `inst.build[...]` / `instances.all` / `inst.*` 埋点）后确认：**T1–T8 的扫描优化都被
> 多实例路径正常复用了，慢的是「实例视图构建」这条新链路没有任何缓存。**

### 1.1 明细

| 环节 | 实测 | 说明 |
|---|---|---|
| `linux_grub_switch`（写 grubenv） | **40 ms** | T1–T3 生效 |
| `remote_boot_switch`（实例分支） | **78 ms** | |
| `inst.build[grub@EFI]` | **0 ms** | 走 `remote_grub_json`（复用 linuxGrub 快照） |
| `inst.build[opencore@EFI/OC]` | **443–451 ms** ×2 | `opencore::view` → `oc_menu::preview` 每次重解析 `config.plist` |
| `inst.build[refind@EFI/BOOT]` | **333–347 ms** | 大头是卷标解析 `cmd.lsblk_label`（refresh 里 18 次≈719 ms） |

## 3. 优化方案（按收益/风险排序）

| # | 方案 | 平台覆盖 | 预期 | 风险控制 |
|---|---|---|---|---|
| **P1** | **实例视图按文件指纹缓存**：key=instanceId，指纹 = `config.plist`/`grub.cfg`/`vars/`/`refind_linux.conf` 的 mtime+size + 安装目录 mtime；命中直接回上次 `BootGroup` | **全平台（宿主）**：Linux/macOS/Windows 同一份 Rust；Web 打接口自动受益；Android/iOS 不调该接口，无影响 | 1.55 s → **1.5–2 ms**（热） | 只缓存成功且完整的结果；`channels` 刷新与切换后失效 |
| **P2a** | Linux：`findmnt`+`lsblk` 卷标按挂载根缓存 60 s | Linux | refind 预演 335 → **112 ms** | 60 s TTL（重命名卷最多 60 s 生效） |
| **P2b** | macOS：`/Volumes/<卷标>` 直取（已有）；`diskutil VolumeName` 兜底结果缓存 60 s | macOS | 兜底不再重复调 diskutil | 同上 |
| **P2c** | Windows：`GetVolumeInformationW` 结果按挂载根缓存 60 s | Windows | 一致（本身不慢） | 同上 |
| **P3** | **OpenCore 视图缓存**：按 `config.plist`/`OpenCore.efi`/`Drivers`/`Kexts`/`ACPI` 的 mtime+size 指纹缓存 10 s；`apply_spec` 与 `fix_launcher_option` 写盘后显式失效 | **全平台（宿主）** | 443 ms → 冷 705 ms（含卷映射首次）/ 热 **0 ms** | 10 s TTL + 写盘/切换显式失效 |
| **P4** | `/api/boot-channels` 5 s 合并缓存 | 全平台（宿主 + Web 直连） | 连续请求 1.5–2 ms | **条数变少视为扫描不全、不覆盖旧缓存**（踩过坑） |
| **P5** | 远端刷新：`remote_boot_info` 3–5 s 缓存 + 探活结果 10 s 复用 | **PC 客户端**（Android/iOS 已有 lastGoodEndpoint 快路径+失败阈值等价机制） | PC 行 6–7.6 s → ~1 s | 探活失败不缓存；**本次未做** |
| **P6** | 启动后台预构建实例组 | 全平台（宿主） | 首屏秒开 | **本次未做**（P1 已让首屏只付一次冷成本） |

> **指纹注意**：ESP 是 FAT32，mtime 分辨率 2 s —— 指纹必须带 `size`，2 s 内的连续改动由 60 s TTL 兜底（可接受）。

## 3.1 实施结果（2026-11-21 实测，本机 Linux）

| 指标 | 优化前 | 优化后 |
|---|---|---|
| `inst.build[grub]` | 0 ms | 0 ms（本来就复用 linuxGrub 快照） |
| `inst.build[refind]` | 335–347 ms | **112 ms** 冷 / **0 ms** 热（P1+P2a） |
| `inst.build[refindplus]` | 329–335 ms | **112 ms** 冷 / **0 ms** 热 |
| `inst.build[opencore]` | 443–451 ms ×2 | 冷 705 ms（首条，含卷映射）/ 第二条 **0 ms**；热 **0 ms**（P3） |
| `/api/boot-channels` | **1.55 s** | **1.5–2 ms** 热；重启后首次 ~0.93 s |
| `remote_boot_info(local)` | 1.5 s | **4 ms** 热（首次 1.3 s） |
| 切换 + 回读 | switch 78 ms + refresh 1.6 s | switch **80 ms** + refresh **263 ms** |
| `remote_boot_info(PC)` | 6–7.6 s | 6.1 s（**未优化**：探活为主，等 P5） |

> 配套已修：`bootInstances.setInstances()` 从「按当次结果剪 `instanceOrder`」改为**只补不删**，
> 扫描不全不再丢页签（`grub`/`refindplus` 曾因此消失）。
