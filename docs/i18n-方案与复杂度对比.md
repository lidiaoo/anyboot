# 项目整体 i18n —— 实现方案与复杂度对比

> 基于本仓库实际结构实测（v0.2.9 时点）。不是泛泛而谈，工作量按本仓库真实代码量估。

## 0. 现状盘点（决定方案的关键事实）

| 面 | 现状 |
|---|---|
| **前端 (Vue3, `ui-vue/`)** | 79 个 `.vue/.ts` 文件含中文，约 **4237 行**含中文字面量；**没有任何 i18n 依赖**（无 vue-i18n） |
| **后端 (Rust, `src-tauri/`)** | **72 个 `.rs` 含中文，约 16513 行**；其中 **~1428 行是 `trace!/log/format!`（日志/内部，可低优先/不译）**；**其余大量是 `Err(format!("..."))` / `message:"..."` —— 直接返给前端显示的「用户文案」** |
| **IPC/HTTP 文案通道** | 前端拿的是 Rust **已拼好的中文字符串**（`api/tauri.ts`: `throw new Error(json.message || ...)`）——**前端 i18n 管不到这些** |
| **Android 原生** | 40+ `.kt/.java`；`strings.xml` 目前只有 `app_name` 一条 |
| **iOS 原生** | 10 `.swift`；无 `.strings` 本地化文件 |
| **设置存储** | `state.rs` 有 `theme` 等字段 → 加 `language` 可仿照，跨端持久化现成 |
| **多端关系** | PC 内置 dist；web/移动端加载桌面 dist（同一套 Vue）；另有 Android/iOS 原生 App |

**核心分水岭**：文案分三层——
- **L1 前端静态文案**（Vue 模板/脚本里的字面量）：vue-i18n 一把梭。
- **L2 Rust 回传的用户文案**（error/message/toast 文本）：**前端 i18n 覆盖不到**，必须在 Rust 侧 i18n 或改传"错误码+参数"由前端翻。
- **L3 原生 App**（Kotlin/Swift）：各自平台 i18n。

---

## 方案 A：只做前端 i18n（vue-i18n），Rust 文案保持中文

**范围**：仅 L1。

- 引入 `vue-i18n`，把 `ui-vue/**` 的 4237 行中文字面量抽成 `locales/zh-CN.json` + `en.json`，模板用 `$t('key')`。
- Rust 返回的 error/message 仍是中文（英文界面下会夹杂中文报错/提示）。
- 语言选择存 settings（仿 theme）。

| 项 | 评估 |
|---|---|
| 工作量 | **中**：4237 行抽取 + key 命名 + 700~1500 个 key；纯前端，无后端改动 |
| 风险 | 低（不改后端接口） |
| 效果 | **半成品**：界面框架英文，但错误弹窗/系统提示/引导项注释等仍是中文 → 英文用户体验割裂 |
| 工期 | 约 **2~4 人天**（含校对） |

**适合**：只想要"多语言外壳"，或只想先验证。

---

## 方案 B：前端 i18n + Rust 文案"错误码化/参数化"（推荐）

**范围**：L1 + L2（Rust 用户文案）。

两种子做法：

### B1. Rust 侧 i18n（后端自带多语言表）
- Rust 里 `Err(format!("文件不存在: {}", p))` → `i18n::t(lang, "err.file_not_found", &[("path", p)])`，Rust 内置 zh/en 词表。
- 好处：改动集中在 Rust 文案处；前端无感（拿到的已是目标语言串）。
- 坏处：**Rust 侧要遍历 ~数千条用户文案**（剔除 1428 日志行后，估计 **1000~2500 条**要抽），跨 72 文件；Rust 无成熟 i18n 生态（手写 `t()` + HashMap/编译期宏，如 `rust-i18n` crate）。

### B2. Rust 返回"错误码 + 结构化参数"，前端翻译
- Rust 改返回 `{code:"err.file_not_found", params:{path}}`，前端 `$t(code, params)`。
- 好处：**所有翻译集中在前端 locales**，单一真相源；Rust 只管码。
- 坏处：**接口契约变更**（error 从字符串变对象），要改 ①Rust 所有 Err 点 ②前端所有消费 error 的地方（toast/弹窗），**面很大、回归风险高**；老版本兼容（web/移动端加载旧/新 dist 混跑）需考虑。

| 项 | B1 | B2 |
|---|---|---|
| 工作量 | **大**（Rust 侧抽 1000~2500 条 + 引入 rust-i18n） | **大**（改契约：Rust 错误点 + 前端消费点，双改） |
| 风险 | 中（主要 Rust，前端稳） | **高**（接口契约 + 全链路回归） |
| 翻译单一源 | 否（前端 json + Rust 词表两份） | **是**（都在前端 json） |
| 工期 | 约 **6~10 人天** | 约 **8~12 人天** |

**适合**：要做到"和远程管理一致、真·完整多语言"。

---

## 方案 C：全端各自原生 i18n（含 Android/iOS 原生 App）

**范围**：L1 + L2 + L3。

- 桌面/网页（Vue）同上 A/B；
- **Android**：`strings.xml`（values/ + values-en/）+ Kotlin 用 `getString(R.string.x)`；当前几乎没抽，**40+ 文件全是硬编码中文**；
- **iOS**：`Localizable.strings`（zh-Hans / en）+ `NSLocalizedString`；10 swift 文件硬编码；
- 语言随系统或 App 内选择。

| 项 | 评估 |
|---|---|
| 工作量 | **很大**：Vue(4237) + Rust(千级) + Android(40 文件) + iOS(10 文件) 四套 |
| 风险 | 高（四端协同、翻译一致性难保证） |
| 工期 | 约 **15~25 人天**（还不含专业翻译/校对成本） |

**适合**：要正式出海、原生 App 也要完整多语言。

---

## 方案 D（轻量折中）：前端 i18n + Rust "高频用户文案"优先翻

- 先做 A（前端全套），Rust 侧**只翻最常露脸的一批**（连接/下载/更新失败、引导提示，约 150~300 条），其余低优先。
- **性价比最高**：80% 体验、30% 工作量。
- 工期约 **4~6 人天**。

## 横向对比总表

| 方案 | 覆盖层 | 语言完整度 | 工作量(人天) | 风险 | 单一翻译源 | 推荐场景 |
|---|---|---|---|---|---|---|
| A 只前端 | L1 | 60%（错误仍中文） | 2~4 | 低 | 前端 | 快速多语言外壳 |
| **D 前端+高频Rust** | L1+部分L2 | **85%** | **4~6** | **低-中** | 前端为主 | **性价比首选** |
| B1 Rust内建i18n | L1+L2 | 95% | 6~10 | 中 | 否(两份) | 桌面/网页完整 |
| B2 错误码+前端译 | L1+L2 | 98% | 8~12 | 高 | 是 | 长期架构、唯一真源 |
| C 全端原生 | L1+L2+L3 | 100% | 15~25 | 很高 | 否(多份) | 正式出海 |

## 建议（针对本仓库）

1. **先做方案 A 的基建**：引入 vue-i18n（Composition API）、建 `ui-vue/src/locales/{zh-CN,en}.json`、`settings.language`（仿 theme 持久化 + 顶栏/设置里切语言）、**先翻引导页 + 设置页 + 远程管理主框架**（最高频）。
2. **并行做"高频 Rust 文案"清单**（D 的部分）：把 error/toast 里最常出现的 ~200 条抽成 `t()`，避免英文界面下动不动弹中文错误。
3. **接口契约不动**（不走 B2），降低回归风险；等语言体系稳定、确需 100% 再评估 Rust 侧 rust-i18n 全量（B1）。
4. **原生 App（C）暂缓**：移动端多数场景是"加载桌面 dist"，桌面/网页做好后移动端 web 形态即刻享受；原生 App 的语言单独排期。

### 落地关键坑（本仓库特有）
- **动态文案拼接**（`format!("{}...{}")`）需改成带占位符的 key + 参数，别硬拼。
- **引导项/GRUB/rEFInd 的标题、OS 名、卷标**是**数据**不是 UI 文案，**不要翻**（翻了就对不上 rEFInd 真实菜单/PreviousBoot 匹配）。
- **web/移动端加载桌面 dist**：语言切换要"下发语言 + dist 重载"或运行时切换 i18n（运行时切更顺）。
- **Rust 的 trace/log 中文不必翻**（1428 行）——内部日志，省大量工作量。
- 翻译质量：机制 key 别自己机翻凑数，英文文案建议人审一遍。
