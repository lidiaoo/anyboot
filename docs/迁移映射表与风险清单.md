## 三、风险清单

| # | 风险 | 等级 | 应对 |
|---|---|---|---|
| R1 | **旧版用 `hidden` 属性把 12 个页面常驻 DOM，新版用 `v-if` 按需挂载** —— 直接比对 DOM 会得出「缺 300 个类」的假象 | 高 | 比对时只看可见元素（已写入 `scripts/ui-compare/`） |
| R2 | **`#app` 是 Vue 新增层，打断 `body > .shell + footer` 布局链** | 高 | `#app { display: contents }`；独立窗用 `min-height:100%` 而非 `height:100vh` |
| R3 | **样式入口若共用会把 hub-inline 的 `body{font:14px}` 污染主窗** | 高 | 按窗口拆 main.css / base.css / win-*.css |
| R4 | **`notify.css` 的 `button.secondary` 会覆盖 legacy** | 中 | 不引入 notify.css（旧版主窗也没引） |
| R5 | **IPC 参数名 camelCase vs snake_case**（`serverId` vs `server_id`）Tauri 反序列化会失败 | 高 | 已与 Rust `fn` 签名逐条比对，0 缺失 |
| R6 | **备份分类 key 就是载荷字段名**，用错会导致备份与手机端互不兼容 | 高 | 已按旧版 `CATS` 逐字对齐 |
| R7 | 旧版主题渲染依赖真实引导器数据，mock 环境无法完整复现 | 中 | 用「CSS 规则数 + class 集合」静态比对 |
| R8 | macOS WKWebView 无 DevTools | 中 | 前端埋点 `[ipc-fail]` 写 trace.log |
| R9 | 旧版 `qrcode.min.js` 是全局脚本 | 低 | 放 `public/`，动态 `<script>` 加载 |
| R10 | 32 个弹层中多数在 mock 下打不开（缺 SFTP/服务端数据） | 中 | 只能比结构，视觉比对受限 |

### 9.4 跨平台 WebView 兼容性说明

| 平台 | WebView | 状态 | 注意 |
|---|---|---|---|
| macOS (Intel) | WKWebView | ✅ 已验证 | 无 DevTools；用 `hub_report_error` 写 trace.log |

| Windows | WebView2 (Chromium) | 预计一致（未在本机验证） | `body{opacity:0}` 需 `markReady()` 处理 |
| Linux | WebKitGTK | 预计一致（未在本机验证） | 字体渲染可能有像素差 |

**已知 WebView 差异（迁移实战发现）**：
1. **无 DevTools**（macOS WKWebView）→ 已用 trace.log 埋点代替
2. **字体渲染**：WKWebView / WebView2 / WebKitGTK 字形度量不同 →
   固定尺寸截图回归只能作辅助报警，需设容差
3. **`#app { display: contents }`**：Vue 挂载层需此规则才能不打断
   `body > .shell + footer` 的 flex 链（已处理）
4. **HTML5 draggable 不可靠**：WKWebView / WebView2 / WebKitGTK 下
   dragstart/drop 行为不一（旧版 boot-adv.js:1926 注释明言「为什么不用
   HTML5 draggable」）→ 旧版即改用 pointer 事件（k-split 分栏），
   新版同样用 pointerdown/setPointerCapture（第 20 轮）；
   唯一保留的 HTML5 draggable 是 rsRouteList 行（第 30 轮，桌面 WebView 实测可用）
5. **输入法守卫**：中文 IME 选词回车（isComposing / keyCode 229）不能当
   提交——旧版 isImeKey 守卫已在 useCtrlEnter 组合式里保留（第 115 轮）
6. **Tauri 2 参数约定**：command 参数名 Rust snake_case → 前端 camelCase；
   结构体参数内层字段仍 snake_case（无 rename_all）——三端 WebView 一致，
   但与 Electron 无此约束不同，是迁移期最大一类 bug 来源（第 42~46/70 轮）
7. **localStorage 不迁移**：Electron 与 Tauri WebView 存储隔离，旧偏好
   （主题/间隔/打开方式）不会自动带入——如需保留用户偏好需另做迁移（未做，
   首启按出厂默认）

## 十三、IPC 参数的三个维度（第 42~47 轮）

Tauri 2 的 command 参数映射规则（**必须三个维度都正确**）：

1. **参数存在性**：前端 `call` 必须传 Rust fn 的所有必填参数（非 Option、非框架注入）
2. **参数命名**：Rust 参数名 `snake_case` → Tauri 2 自动转 **`camelCase`** 给前端。
   前端必须传 camelCase（如 `server_id` → `serverId`）
3. **参数包装**：若参数类型是结构体（`server: HubServer`），前端要包一层
   `{ server: {...} }`；**结构体内部字段仍是 snake_case**（无 `rename_all`）

### 各轮发现与修复
| 轮 | 维度 | 发现 |
|---|---|---|
| 3 | 存在性 | 109/109（仅查存在）|
| 42 | 命名 | 误判 3 个（实际 mock 兼容掩盖）|
| 43 | 存在性(必填) | 9 个无参调用必填命令 |
| **45** | **命名（真机）** | **12 个 camelCase 错误（含把 42 改反的）** |
| **46** | **包装** | **2 个缺 `{ server }` 包装** |
| 47 | 验证 | 反序列化测试确认 payload 结构正确 |

### 关键教训
- **mock 宽容（`args.serverId || args.server_id`）会掩盖真实 bug**，
  42/43 轮的"修复"和严格模式"0 违规"都因此失真
- **只有真机 `trace.log` 能可靠暴露 IPC 参数错误**
- Tauri 2：外层 camelCase，内层结构体字段 snake_case
