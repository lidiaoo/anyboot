# 引导器下拉/列表统一规范（必须遵守）

> 2026-11-15 定案（用户）：**所有引导器的「选择下次启动」弹窗、列表、托盘菜单，一律只用 GRUB 通用样式**，
> 只是数据不同。**禁止为任何引导器（rEFInd / RefindPlus / GRUB / systemd-boot / OpenCore / Clover /
> 以及以后新引入的）再写一套独立的行样式或独立渲染组件。** PC / Web / 移动端（Android/iOS）/ 托盘同理。

## 一、唯一的渲染样式（基准 = GRUB 通用样式）

每个引导器的弹窗结构完全一致（自上而下）：

```
┌─ 弹窗卡片（PC/Web：居中卡片，宽≈屏宽-24、圆角14；移动端同款居中卡片）
│  标题行：<引导器名> 启动项        <电脑名/地址>  ✕
│  条目文字格式 chips：跟随电脑 / 极简 / 简易 / 中等 / 原始 / 复杂   ← 所有引导器都有
│  ★ 悬浮置顶行（sticky，滚动不动）：[下次启动] 图标 组名 › 子名 / 条目名   ✓
│  ── 滚动列表（只有这一段滚动）──
│  ▾ 图标 组名                        N 项        ← 组头（右对齐灰字计数）
│     ↳ 图标 子名                     来源标签     ← 子项（左竖线缩进 + 右侧灰 tag）
│     图标 条目名                    （顶层项：无缩进）
│     子行小字：卷 · 路径（sub）                    ← OC 等有说明内容的引导器
│     子行小字：备注（note）
│  底部：整宽「取消」按钮
└─
```

**要点（不容偏差）**：
1. **行结构只有一种**：`↳(子项缩进箭头) + 图标 + 名 + 右侧灰 tag + 行下 sub/note 小字`。
2. **组头只有一种**：`▾ 图标 组名` + 右侧 `N 项`。
3. **置顶副本只有一种**：`[下次启动] 标签 + 图标 + 名（组名 › 子名）+ ✓`，且**悬浮固定**（滚动列表时不动）。
4. **OpenCore 等引导器** = 除了行下多 sub/note 说明小字之外，与 GRUB 行完全一样；**没有独立的卡片样式、
   没有「设为默认」按钮、没有提示展开区（⚠️）/提示词**（"提示按钮和提示词在本系统不可见"）。
5. **格式 chips 所有引导器都显示**（不只 GRUB）——格式切换对所有引导器的行文字生效。
6. **busy（自动刷新/切换中）不阻止打开弹窗**——否则 2s 轮询窗口里按钮几乎恒 disabled、点击被吞（穿透到卡片跳电脑页）。
7. **只读行（spec/value 为空的兜底项，如 OC 的 Reset NVRAM）**：置灰、点击只提示、不发起切换。

## 二、实现方式：数据层转换 → 唯一渲染层

**只允许一处渲染**（GRUB 通用渲染），各引导器的差异全部消化在**数据转换层**——
把各自的后端数据转成「GRUB 原料」统一模型，再喂给唯一渲染函数：

### 统一模型（GRUB 原料）
```
BootOption {
  value            // 可切值（空 = 只读兜底行，如 OC 的 Reset NVRAM）
  label            // 显示名（内核名已 stripKernel 去 vmlinuz-/linux- 前缀）
  kind             // mac/win/linux/auto/tool → 图标
  header           // true = 组头行
  tag              // 行右侧灰字（rEFInd 子项：默认项/折叠内核/macOS 诊断…；OC：类型 · 来源）
  grubSub          // 行下小字：卷 · 路径
  grubNote         // 行下小字：备注
  grubName / grubKernels / grubSubmenuId / grubVariants / grubChainloader / grubClassRaw
                   // GRUB 原料（组头/子项/变体折叠/行文字格式都靠它们）
}
BootGroup { options[], current, grubGroupNames{submenuId→组名}, listFormat, … }
```

### 各端唯一渲染函数（禁止再写第二套）
| 端 | 唯一渲染 | 数据转换入口 |
|---|---|---|
| PC/Web | `GrubList` + `GrubEntry`（`ui-vue/src/components/boot/`） | `BootList` 的 entries（`simRows`/`grubEntries`/`channelEntries` 只做**数据**转换） |
| Android | `grubDisplayRows()` + 弹窗行 Composable（`ComputerListActivity.kt`） | `parseGrub` / `parseRefindSim` / `channelToBootGroup` → BootGroup（grub 原料） |
| iOS | `GrubFormat.displayRows()`（`Model/BootGroup.swift`）+ 弹窗 SwiftUI 行 | `BootParser.parseGrub / parseRefindSim` / `channelToBootGroup` |
| 托盘 | `menu_model::grub_menu_nodes()`（Rust） | refind/channel 的 view → GrubView 转换（见 §四） |

**新引导器接入步骤**（唯一的做法）：
1. 写一个**数据转换**：新引导器的后端数据 → 统一 BootOption/BootGroup（grub 原料字段）。
2. **不写任何新渲染**：直接走该端唯一的渲染函数/组件。
3. 行下需要说明内容 → 填 `grubSub/grubNote`；行右侧要标签 → 填 `tag`；不可切 → `value` 留空。
4. 弹窗/列表/托盘自动获得：chips、悬浮置顶、组头/子项、变体折叠、只读置灰、行下说明。

## 三、禁止事项（历史教训，不许再犯）
1. **禁止**为某引导器写独立渲染组件/函数（曾经有：Android `refindSheetRows`、`ChannelPickerContent`、
   `ChannelMenuRowView`，iOS `refindRows`、`channelPickerContent` 独立卡片 —— 均已删除）。
2. **禁止**在行渲染里按 `kind != GRUB` 之类的条件分支画不同元素（BootDot、按钮、提示区）。
3. **禁止** OC 弹窗出现「设为默认 ⤴」按钮、⚠️ 提示展开区、Ctrl+Enter/NVRAM 提示词。
4. **禁止** rEFInd 子项显示 `vmlinuz-linux-` 前缀（必须 stripKernel）。
5. **禁止**置顶副本作为普通列表行渲染（必须悬浮固定，滚动不动）。
6. **禁止** `showGroups`、`flat` 之类的按引导器开关样式（OC 的条目 submenu 为空，天然不出组头，无需特判）。
