# AnyBoot 移动端客户端

**定位**：手机不是「另一个 AnyBoot」，而是**远程控制客户端** —— 和 web 端一模一样，
通过局域网调用电脑端 AnyBoot 内置 HTTP 服务（默认 `12300`，token 鉴权）的那套 API。

```
┌───────────────┐   http://192.168.0.120:12300   ┌──────────────────────┐
│ 手机 App      │ ─────────────────────────────▶ │ 电脑 A · AnyBoot     │  标签：书房台式机 · 有线
│ 标签①WebView  │                                │  内置 HTTP 服务       │
│               │   GET  /                （前端页面）                  │
│               │   GET  /health          （探活 + machineId）          │
│               │   GET  /api/ws          （推送快照，默认）            │
│               │   GET  /api/ui-state    （轮询兜底 / 手动刷新）        │
│               │   POST /api/ui-command  （下发命令）                  │
│               │        ↑ 同一个标签、同一个 WebView                    │
│               │   192.168.0.131:12300 不通就自动换 10.0.0.7:12300     │
├───────────────┤   http://192.168.1.20:12300    ┌──────────────────────┤
│ 标签②WebView  │ ─────────────────────────────▶ │ 电脑 B · AnyBoot     │  标签：客厅小主机
└───────────────┘                                └──────────────────────┘
     标签数 = 电脑数（不是 IP 数）；一台电脑的多块网卡是它「一个标签内部的多个候选地址」
```

## 快速上手（5 步）

1. **电脑端先就绪**：打开 AnyBoot → **基本设置 ▸ 远程控制** → 打开 HTTP 服务，确认端口
   （默认 `12300`），并记下那行 **访问令牌 token**。再点一下旁边的 **打开 Web 页面**
   自测一下：浏览器能打开就说明局域网这条路通了。
2. **手机连同一个网络**：手机连的路由器 / 热点必须和电脑是同一个（别用手机流量）。
   想看电脑 IP：Windows `ipconfig`，macOS/Linux `ifconfig`，找 `192.168.x.x` 那种地址。
   多块网卡就有多个地址 —— **都填进去**，客户端自己会用能通的那个。
3. **装 App**：
   - Android：`adb install -r mobile/android/app/build/outputs/apk/debug/app-debug.apk`
     （或直接把 APK 拷进手机点安装）；
   - iOS：按 [`ios/README.md`](ios/README.md) 用 Xcode 把 `ios/AnyBootRemote/` 拖进工程后运行。
   - **不想装也行**：手机浏览器直接开 `http://<电脑IP>:12300`，效果一样，只是没有多标签。
4. **填第一条（= 第一台电脑）**：首次启动会弹表单 —— **分组**填「书房台式机」这类电脑名、
   **服务端名**填「有线网卡 / 5G WiFi」（可留空）、**地址**填 `192.168.0.120:12300`
   （有多个网卡就**一行一个**全填进来；也可以把整条带 token 的 URL 粘进来，token 会自动拆出来）、
   **token** 可留空（留空时页面自己会弹框要）。
5. **再加一台电脑 / 日常使用**：标签栏 `＋` 加第二台电脑（想给**同一台**电脑补地址，
   **分组填同一个名字**即可 —— 会自动并进那个标签，不会多出一个标签）；
   **长按标签**改这一条；`☰`（iOS 是 `⋯`）看列表、删除、切标签、**一键合并同一台电脑的重复记录**；
   想让 App 一打开就把所有电脑都连上，在菜单里勾 **「启动时连接全部服务端」**；
   想看走推送还是轮询，菜单里有 **「传输方式」**。

> 连不上时 App 会给一个**重试面板**，别急着重装 —— 九成是第 1、2 步没对上
> （服务没开 / 不在同一网段 / 端口不是 12300）。

## 一台电脑 = 一个标签（多网卡怎么处理）

一台电脑可能有多块网卡（有线 + WiFi + 虚拟网卡）、或者 DHCP 每次给不同 IP ——
**这些地址是同一台机器，只该占一份页面**。所以客户端按「**一条记录 = 一台电脑**」
来组织，地址是这条记录内部的**有序候选列表**：

- 标签栏里**一个标签就是一台电脑**（标签数 = 电脑数，不是 IP 数），
  标签文本 `组名 · 服务端名`，分组配色恒定（扫一眼分得清是哪台机器）；
- 地址框支持**多行**，每行一个地址，都是同一台电脑的候选地址；
- 加载时**首选地址不通就自动换下一个**，还是同一个标签、同一个 WebView
  （会提示「这个地址不通，换一个地址重试：…」），换地址期间标签上的圆点会变橙；
- **哪个地址通，就把它记成首选** —— 下次开机直连它，DHCP 换过 IP 也能自己找回来；
- 候选地址**全试完**才认为这台电脑连不上，这时重试面板会把试过的地址全列出来；
- **token 建议填进 App**：cookie 是按「来源站点」存的，换了地址（换了 IP）就是另一个站点，
  页面会重新读一次 URL 里的 token —— App 里存着 token 时换地址是无感的，没存就可能再要一次；
- 标签左侧圆点是该电脑的在线状态（灰=未连 / 橙=加载中 / 绿=已加载 / 红=连不上）；
- 多台电脑**同时在线**：每台一个 WebView，切换标签不重新加载。

### 「是不是同一台电脑」怎么判断

优先用**电脑端的机器标识**：客户端保存地址后会顺手探一次 `GET /health`（免 token），
里面带这台机器的 `machineId`（首次运行生成、存在 `settings.json`、重启不变）。

- 探到 `machineId` 和已有记录相同 → **自动把地址并进那条记录**，不新建标签（会提示「已并入同一台电脑」）；
- 一个地址都还没填 token 也能探 —— `/health` 免鉴权，所以归并不依赖 token；
- 拿不到标识（老版本服务端）时退回**「分组名相同 = 同一台电脑」**这个约定，
  所以只要你把同一台机器的地址填一个分组，照样合并；
- 已经有「每个 IP 一条记录」的老配置：在服务端列表里点
  **「合并同一台电脑的地址」**，一键收成「一台电脑一份页面」。

两端都实现了同一套：Android 见 `android/README.md`，iOS 见 `ios/README.md`。

## 刷新与传输方式（推送 / 轮询）

页面默认走**推送通道**（`/api/ws`，WebSocket）：电脑那边一改，手机上几百毫秒内就到，
空闲时几乎不发包 —— 不用再每 2 秒拉一次，手机省电、也不会有「最坏差 2 秒」的迟滞。

**在 App 里选**：菜单里那一项 **「传输方式（自动 / 推送 / 轮询）」**：

| 档位 | 含义 |
| --- | --- |
| 自动 | **默认**。先试推送，连不上就落到 2 秒轮询（页面照常可用），后台继续试着把推送接回来 |
| 推送 | 只用 WebSocket。断开就提示「推送通道已断开，正在重连…」并退避重连（不会偷偷改回轮询） |
| 轮询 | 只用 HTTP，每 2 秒拉一次 `/api/ui-state`。穿代理 / NAT 最稳 |

选的值存在 **App 侧**（Android `SharedPreferences` / iOS `UserDefaults`），每次加载页面时以
`?transport=` 追加到地址上交给网页决定 —— 因为网页的 localStorage 是按**来源站点**存的，
这台电脑换块网卡就换了地址（= 换来源），只存网页端的话偏好会跟着丢。选完**不立刻重载页面**
（那会打断你正在看的东西），下一次加载生效；当前页面上也能在**横幅的下拉里即切即用**（同一个偏好）。

**刷新**有两处，手机上都顺手：

- **下拉刷新**：在页面顶部**往下拉** → 「下拉刷新」→「松开刷新」→「正在刷新…」，松手即刷新；
  只有页面真的在顶部时才接管手势，在 token 弹窗里滚动不会误触发；
- **横幅上的「刷新」**：点一下立刻抓一份快照（提示「已刷新」），不等下一拍。

推送正常时这两个都用不上，但它们是兜底：某一拍丢帧、或你在电脑上刚改完设置，拉一下立刻对齐。
（App 菜单里还有「重载当前页面 / 全部重载」，那是重新加载整个页面 —— 刷新只重新取快照。）

## 为什么不做原生移植

安卓/iOS 上读不到 ESP、没有 GRUB、没有托盘和窗口贴边这些概念；
把服务端能力原样搬到手机上既没意义也没权限。真正需要的只是**在手机上调那套已有 API**，
而电脑端**已经**实现了：静态前端托管 + `/api/ui-state` 轮询 + `/api/ui-command` 白名单命令，
并且前端本身做过移动端响应式适配（窄屏分栏堆叠、输入框防 iOS 缩放等）。
所以移动端要做的只剩一个「能记住多个地址、能同时连多台电脑的 WebView」——
外加把**同一台电脑的多个地址**收进同一条记录，别让它变成「一个网卡一个标签」。

## 两端对应关系

| | Android | iOS |
| --- | --- | --- |
| 目录 | `mobile/android/` | `mobile/ios/` |
| 技术 | Java + 系统 `WebView` | Swift + `WKWebView` |
| 多电脑 | 标签栏 + 每台电脑一个 `WebView`（懒创建） | 标签栏 + 每台电脑一个 `WKWebView`（常驻） |
| 多网卡 | 一条记录多个候选地址：失败自动换下一个，成功记成首选 | 同左（地址索引 + `reloadToken` 换 URL，不换实例） |
| 自动归并 | 保存后探 `/health` 的 `machineId`，同机地址并进一条 | 同左（`HealthProbe.swift`） |
| 明文 HTTP | `android:usesCleartextTraffic="true"` | ATS `NSAllowsArbitraryLoads` |
| 局域网授权 | 无需额外声明 | `NSLocalNetworkUsageDescription`（iOS 14+ 必需） |
| 构建 | `gradle assembleDebug`（本机可出 APK） | 需要 Mac + Xcode（本机无法构建） |

> 顺便一提：**不装 App 也能用** —— 手机浏览器直接打开 `http://<电脑IP>:12300` 效果完全一样，
> App 只是省掉输地址、支持一台手机同时连多台电脑、一台电脑多个地址自动切换、并加了重试面板。

## 服务端需要动什么吗

不需要。当前电脑端已经具备移动客户端要用的一切：

- `GET /`、`/ui/*`：托管前端页面（无需 token，页面本身不含机密）
- `GET /health`：探测是否在跑 + **这台机器是谁**（`machineId` / `machineName`，免 token，
  客户端靠它把同一台电脑的多个 IP 归并成一份页面）
- `GET /api/ws`：推送快照（默认通道，WebSocket；握手用 `?token=` 或 cookie 鉴权）
- `GET /api/ui-state`：状态快照（轮询兜底、手动刷新、下拉刷新）
- `POST /api/ui-command`：`{cmd,args}` 白名单命令，与电脑端前端一一对应
- 鉴权：`X-Auth-Token` 头 / `?token=` 查询参数（验证通过后前端写 cookie）

GUI 专属命令（文件夹选择框、打开系统设置等）在服务端已被显式拒绝并返回 `gui_only`，
移动端只会收到「该操作需要在电脑上完成」这类明确错误，不会误伤。

## 手机上点「切换系统」会发生什么

**电脑会弹一个授权窗让你确认** —— 手机端选系统不会直接改引导项，而是先变成一条**远程请求**：
电脑上弹出「远程请求（HTTP）」，写明**来源客户端 IP、渠道、发起时间**，电脑前的人点「立即执行」
（或等倒计时到点）才真的切换，点「取消」就作废。手机页面会同时提示「已发送到本机：…」。

这是有意的设计：切系统和重启/关机一样属于「得在电脑跟前点个头」的事。所以**手机上的
「立即执行」按钮是灰的** —— 要执行得回电脑前点（或者什么都不做、等倒计时自动执行），
手机上只能「取消」撤回自己刚发的那条请求。电脑端默认允许远程请求弹本机授权框
（基本设置里可关）；关掉之后远程请求仍会执行，只是不再弹框。

另外，手机刚打开 App 时如果电脑端服务正在重启、或 WiFi 刚连上还没通，页面**不会定格成空白** ——
它会每 2 秒重试，一连上就自己接回远程模式，不用手动刷新（浏览器版同样如此）。
