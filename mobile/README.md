# AnyBoot 移动端客户端

**定位**：手机不是「另一个 AnyBoot」，而是**远程控制客户端** —— 和 web 端一模一样，
通过局域网调用电脑端 AnyBoot 内置 HTTP 服务（默认 `12300`，token 鉴权）的那套 API。

```
┌───────────────┐   http://192.168.0.120:12300   ┌──────────────────────┐
│ 手机 App      │ ─────────────────────────────▶ │ 电脑 A · AnyBoot     │  标签：书房台式机 · 有线
│ 标签①WebView  │                                │  内置 HTTP 服务       │
│               │   GET  /                （前端页面）                  │
│               │   GET  /api/ui-state    （轮询快照）                  │
│               │   POST /api/ui-command  （下发命令）                  │
├───────────────┤   http://192.168.0.131:12300   ┌──────────────────────┤
│ 标签②WebView  │ ─────────────────────────────▶ │ 电脑 A · AnyBoot     │  标签：书房台式机 · 5G WiFi
├───────────────┤   http://192.168.1.20:12300    ┌──────────────────────┤
│ 标签③WebView  │ ─────────────────────────────▶ │ 电脑 B · AnyBoot     │  标签：客厅小主机
└───────────────┘                                └──────────────────────┘
     每个标签一个独立 WebView（可同时在线）；标签名 = 组名 ＋ 服务端名
```

## 快速上手（5 步）

1. **电脑端先就绪**：打开 AnyBoot → **基本设置 ▸ 远程控制** → 打开 HTTP 服务，确认端口
   （默认 `12300`），并记下那行 **访问令牌 token**。再点一下旁边的 **打开 Web 页面**
   自测一下：浏览器能打开就说明局域网这条路通了。
2. **手机连同一个网络**：手机连的路由器 / 热点必须和电脑是同一个（别用手机流量）。
   想看电脑 IP：Windows `ipconfig`，macOS/Linux `ifconfig`，找 `192.168.x.x` 那种地址。
3. **装 App**：
   - Android：`adb install -r mobile/android/app/build/outputs/apk/debug/app-debug.apk`
     （或直接把 APK 拷进手机点安装）；
   - iOS：按 [`ios/README.md`](ios/README.md) 用 Xcode 把 `ios/AnyBootRemote/` 拖进工程后运行。
   - **不想装也行**：手机浏览器直接开 `http://<电脑IP>:12300`，效果一样，只是没有多标签。
4. **填第一条服务端**：首次启动会弹表单 —— **分组**填「书房台式机」这类电脑名、
   **服务端名**填「有线网卡 / 5G WiFi」（可留空）、**地址**填 `192.168.0.120:12300`
   （也可以把整条带 token 的 URL 粘进来，token 会自动拆出来）、**token** 可留空
   （留空时页面自己会弹框要）。
5. **再加一条 / 日常使用**：标签栏 `＋` 加第二台电脑或第二个 IP（同一台电脑的多条地址
   **填同一个分组**）；**长按标签**改这一条；`☰`（iOS 是 `⋯`）看列表、删除、切标签；
   想让 App 一打开就把所有服务端都连上，在菜单里勾 **「启动时连接全部服务端」**。

> 连不上时 App 会给一个**重试面板**，别急着重装 —— 九成是第 1、2 步没对上
> （服务没开 / 不在同一网段 / 端口不是 12300）。

## 多服务端与分组

一台电脑可能有多块网卡、或者 DHCP 每次给不同 IP —— 这些地址其实是同一台机器。
所以客户端按「**分组 = 一台电脑**」来组织：

- 标签栏里每个标签是一个服务端，标签文本是 `组名 · 服务端名`（未分组就只显示服务端名）；
- 同一个分组的标签描边同色（颜色由组名哈希决定），扫一眼就知道哪几个标签是同一台机器；
- 标签左侧的圆点是该服务端的在线状态（灰=未连 / 橙=加载中 / 绿=已加载 / 红=连不上）；
- 每个标签一个独立 WebView，**可以同时连着多台电脑**，切换标签不重新加载；
- 菜单里「启动时连接全部服务端」= 打开 App 就把所有标签一起连上。

两端都实现了同一套：Android 见 `android/README.md`，iOS 见 `ios/README.md`。

## 为什么不做原生移植

安卓/iOS 上读不到 ESP、没有 GRUB、没有托盘和窗口贴边这些概念；
把服务端能力原样搬到手机上既没意义也没权限。真正需要的只是**在手机上调那套已有 API**，
而电脑端**已经**实现了：静态前端托管 + `/api/ui-state` 轮询 + `/api/ui-command` 白名单命令，
并且前端本身做过移动端响应式适配（窄屏分栏堆叠、输入框防 iOS 缩放等）。
所以移动端要做的只剩一个「能记住多个地址、能同时连多台电脑的 WebView」。

## 两端对应关系

| | Android | iOS |
| --- | --- | --- |
| 目录 | `mobile/android/` | `mobile/ios/` |
| 技术 | Java + 系统 `WebView` | Swift + `WKWebView` |
| 多服务端 | 标签栏 + 每标签一个 `WebView`（懒创建） | 标签栏 + 每标签一个 `WKWebView`（常驻） |
| 明文 HTTP | `android:usesCleartextTraffic="true"` | ATS `NSAllowsArbitraryLoads` |
| 局域网授权 | 无需额外声明 | `NSLocalNetworkUsageDescription`（iOS 14+ 必需） |
| 构建 | `gradle assembleDebug`（本机可出 APK） | 需要 Mac + Xcode（本机无法构建） |

> 顺便一提：**不装 App 也能用** —— 手机浏览器直接打开 `http://<电脑IP>:12300` 效果完全一样，
> App 只是省掉输地址、支持一台手机同时连多台电脑、并加了重试面板。

## 服务端需要动什么吗

不需要。当前电脑端已经具备移动客户端要用的一切：

- `GET /`、`/ui/*`：托管前端页面（无需 token，页面本身不含机密）
- `GET /health`：探测是否在跑
- `GET /api/ui-state`：状态快照（轮询用）
- `POST /api/ui-command`：`{cmd,args}` 白名单命令，与电脑端前端一一对应
- 鉴权：`X-Auth-Token` 头 / `?token=` 查询参数（验证通过后前端写 cookie）

GUI 专属命令（文件夹选择框、打开系统设置等）在服务端已被显式拒绝并返回 `gui_only`，
移动端只会收到「该操作需要在电脑上完成」这类明确错误，不会误伤。
