## 文件浏览免先开终端（第五十二轮，用户反馈「打开一次终端才能连文件比较麻烦」）

## 传输断点续传（第五十三轮，用户反馈「PC 端传输中的文件断点续传和暂停继续还没做，点暂停没反应」）

- **根因与方案取舍**：按钮其实接了事件（c0fc7f0 已有 `hub_sftp_transfer_ctl`），但旧实现是 **SIGSTOP 冻结 sftp 子进程**——libc 的 SIGSTOP/SIGCONT/`kill` 在 Windows 上不存在（`libc` 不给 Windows 导出），三端同源代码只有 Linux/macOS 假装能编译；且 SIGSTOP 跨不了重启、sftp 进程一死偏移就没了，算不上断点续传。重做：**暂停=杀子进程留半截文件+记断点；继续=新起子进程 `reget`/`reput` 从已传字节接着传**（OpenSSH sftp 内建 `-a` 续传语义，man 确认），与手机端 TransferManager 三键对齐。

- **实现**（hub_sftp.rs）：`XferTask{key=dir|remote|local,…,paused}`（Ser+De）；State 加 `paused` 清单 + `transfer-queue.json` 落盘（tmp+rename，坏 JSON 按空表）+ setup `load_queue_at_startup` → **应用重启后传输页还能继续/放弃**。running 表改 `RunningXfer{window,task,child}`（spawn 时快照任务）。ctl 四动作：pause=杀+upsert；resume=load_server_by_id→ensure_control→尺寸校验（远端<断点拒绝；up 本地源没了拒绝）→**先 spawn 再 remove_paused**（spawn 失败记录还在）；abandon|cancel（cancel 是别名）=删半截（up 走 sftp rm）+删记录。新增 `hub_sftp_transfer_list`（已注册）。`spawn_progress_poller`：down 看本地大小、up 每 ~1.5s 摸**远端**半截大小；收尾三态=成功 done（顺手清竞态断点）/**同键新进程已接管（Arc::ptr_eq）静默**/在清单里 paused；**其余（网络断）自动 upsert 进断点清单**再发 failed（中断=可续传的暂停）。上传从整批同步 run_sftp_batch 改成**每文件一个子进程**（可独立暂停/放弃、进度可见、失败不连坐）。进度事件全带 `key`；`emit_progress` 只发文件窗（传输页走轮询）。

### 续：100% 已暂停死卡（用户实机截图「↓ 已暂停 openwrt.img 100% · 断点 1022M」）
