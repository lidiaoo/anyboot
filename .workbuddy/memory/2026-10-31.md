## Linux 轮询重置循环修复（cf04587）
- 真机 bug：分辨率监听让窗口反复重置、滚动位置每 1.5s 被打回顶部。根因：display_change_watch 非 Windows 分支签名含显示器 position 且无抖动过滤 —— Wayland position 可能全 0 或在 0/真实值间抖，签名每拍不同 → 每拍重置。
- 修复：签名去 position 只留（宽、高、scale×100 量化）；新签名连续 2 拍一致才认（A/B 抖动永远凑不齐）；确认/首见都写 trace（旧→新签名），再犯日志直接给答案。Windows 分支不动（已验证：签名无 position、DPI 整数）。
- 527 tests 全绿。教训：轮询比对类逻辑必须有「连续 N 拍确认」；position 永远不该进签名。

## Linux 窗口 530ms 自激环真根因（65e1ffb）
- 用户反馈「问题依旧 窗口仍然闪」。cf04587 修的 display_change_watch 在 Linux 根本没接线（lib.rs spawn 是 cfg(windows)，ebae6fd「补齐 macOS/Linux」漏改 cfg）——Linux 轮询一直是死代码，trace 里零 display-watch 记录早就说明了这点。
- 真凶（startup-debug.log 铁证）：center main -> (1460,274) 每 ~530ms 无限循环。燃料链 = 前端 Resized 监听 → 500ms 回写 set_window_size → Rust set_main_window_size 无条件 set_size（GTK 同值也发 configure）+ recenter → Moved 回声 → 循环。Windows 同值 set_size 不发 WM_SIZE 所以测不出来。4K 屏（920x1440 物理，Muffin 标题栏 64）。
- 断环三处：① set_main_window_size 同值（±2px）跳过 set_size/重居中（主力）；② 前端回写同值守卫（±1px，windowResizePersistLast，滑条路径也记账）；③ center_echo_still_held 用真实几何（窗框/客户区任一贴落点=没动）做居中回声纵深防御。
- 连带把 spawn cfg 放开到 desktop（三端同策略真正生效，Linux 轮询分支 cf04587 已加固）。528 tests 全绿。
- 教训：①取证文件是 startup-debug.log（永远写），trace.log 默认关——查窗口几何问题先看它；②「同值 set_size 在 GTK 会发 Resized」是跨端差异，回写类逻辑必须带同值守卫；③cfg 分支接线要核对（又是 ebae6fd 教训）。

## Linux GRUB 扫不到任何 ext4（本次提交修复）
- 用户报「grub 提示没扫到任何 ext4 分区」。合并 7cc50b3 里唯一动了 grub 逻辑的是 b69f60d（移除 Linux「本机行」特例，linux_grub.rs 净 -198/+29）；前端 grub 相关净变化 0。
- 真因不是本机没有 Linux 分区（本机 10 块 ext4）：`system_partitions_linux()` 用 `lsblk -J` 解析时**只过顶层**再筛 `type=="part"`，而 lsblk 的 JSON 是树 —— 顶层 `blockdevices` 只有整盘，分区全在 `children` 里 → 恒空。lsblk 退出码 0、输出完整，所以完全没有报错迹象。
- 这个 bug 从 0d7d59c（10-30 00:14 fstab 遍历）起就存在，只是 probe_host() 的「本机行」直读 /boot/grub 兜住了本机，看不见；b69f60d 拿掉本机行后，全量遍历成唯一来源，立刻暴露。
- 取证手法：`sudo -n /usr/lib/anyboot/anyboot-priv --linux-grub-probe --out /tmp/x.json` + `strace -f -e trace=execve,write` 直接看助手进程真拿到了什么。(1) 快；不用改代码。
- 修复：抽出 `parse_lsblk_parts()`，先序递归 children（LUKS/LVM 再嵌一层也走到，但只收 part 节点）；`use_children` 回归测试用真机形状夹具。真机 `live_probe`（root）实测扫出 10 块 ext4、8 份 grub.cfg，Arch 根 nvme0n1p9 命中 ESP 挂载 UUID=E537-7F31 → /boot/efi。529 tests 全绿。
- 注意：修的是**助手侧**代码，装好的 /usr/lib/anyboot/anyboot-priv 是旧构建，必须重装免密组件（或整个 app）才生效。
- 遗留：LVM/LUKS 布局仍扫不到（crypt/lvm 节点 type 不是 part，且 part_number=0 会被 probe_raw 跳过）；本机无此布局，未改。
