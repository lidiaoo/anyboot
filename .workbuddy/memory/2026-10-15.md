## appimage 打包链路真正修通（用户 7ce6504 又把 appimage 加回 build:linux 后）
- 用户真机 `NO_STRIP=1 npm run build:linux` 仍挂 `failed to run linuxdeploy`（deb+rpm 正常）。verbose 抓真报错：**linuxdeploy（缓存版 1-alpha 659c9db，2024-07 build 10）内置 strip 的 binutils 太老，不认识 CachyOS 库的 `.relr.dyn`（SHT 0x13, DT_RELR）段，所有库 strip 全挂 → 非零退出**。`NO_STRIP=1` 环境变量对 linuxdeploy 无效。
- 修法（一条命令级）：把 `~/.cache/tauri/linuxdeploy-x86_64.AppImage` 替换为 continuous 新版（build 369，内置 binutils 2.47，实测能剥 webkit RELR 库）。旧版备份在 `linuxdeploy-x86_64.AppImage.bak-2024`。替换后 `npx tauri build --bundles appimage` 直接成功（真机非沙箱），105MB，--appimage-offset=944632、解包验过 anyboot+webkit。
- 第二个偶发坑：linuxdeploy-plugin-appimage 下载 type2 runtime 偶发 TLS/连接失败（"server returned status code 0"）→ 绕行：runtime 已存 `~/.cache/tauri/runtime-x86_64`，重跑时 `LDAI_RUNTIME_FILE=~/.cache/tauri/runtime-x86_64` 前缀即可（扒自插件二进制的 strings，插件认这个环境变量）。
- 修正昨日结论：容器/沙箱里 fuse/chown 限制依旧，但**真机上 tauri 原生 appimage 链路可用**；沙箱内跑打包仍建议走 build:linux-portable（jammy 脚本）或只出 deb/rpm。
- 手动复现命令链（备用）：tauri build 先重建 AppDir（失败也没关系）→ `LDAI_RUNTIME_FILE=... APPIMAGE_EXTRACT_AND_RUN=1 ~/.cache/tauri/linuxdeploy-x86_64.AppImage --appimage-extract-and-run --verbosity 1 --appdir <AppDir> --plugin gtk --output appimage`。注意 AppDir 跑过一次就别重复喂（gtk 插件 rpath 二次设置报"文件已存在"）。
