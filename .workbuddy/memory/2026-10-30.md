- 提权链不动：--linux-grub-write 子命令（main.rs ⓪.56 root 硬校验）经 spawn_privileged 三通道（免密助手→pkexec→密码）。

## 免密组件永远进不了 ready 的真根因（8f16654）
- 用户反馈「重装了免密提权还是回落到 pkexec」。排查：/var/lib/anyboot/priv.json（00:57, v0.1.0）、/usr/lib/anyboot/anyboot-priv（00:57 新副本）齐全，root 直跑 --linux-grub-probe 成功 → 安装本身没问题。
- 真根因：本机 /etc/sudoers.d 是 0750 root:root，普通用户 stat 授权文件 EACCES → Path::exists()=false → classify 判 stale → status 永远 != ready → status 闸门的路径（GRUB 免密扫描、启动自动挂载 ESP）全被跳过直落 pkexec；而走 spawn 阶梯（helper_ready 只查文件）的写入路径一直正常——这正是「写 NVRAM 能成、扫描却弹框」的原因。
- 修复：sudoers_stat_visibility 三值化（Ok=装 / EACCES=不可知回落 meta / 其它=没装）；meta 只在 visudo+落盘成功后写，可信。连带修好所有 status()==ready 闸门。
- 之前的「重装免密组件」前置动作全部是治标——该用户机器上 status 从来没 ready 过。
- 教训：Path::exists() 对无权限路径返回 false 不是「不存在」；涉及 /etc/sudoers.d 这类 0750 目录的判定必须处理 EACCES。另：本轮再次踩沙箱视图缓存坑（一度 ls /var/lib/anyboot 报 No such file，实际存在）+ git commit 输出错乱（实际成功）。
