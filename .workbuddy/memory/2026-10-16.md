- 证据：保存后 `passwordEnc` 非空，但连接时 `needsManualPassword` 仍为 true；加日志拿到
  `KeyVault.decrypt 失败: javax.crypto.AEADBadTagException`（GCM tag 校验失败 = 密钥不对）。
- 影响面**远不止密码**：私钥 PEM（`privateEnc`）、密钥口令（`keyPassphraseEnc`）都走 KeyVault，一起作废；
  而**打开编辑框回显密码就会调一次 decrypt** → 连别的条目也一起废掉。
- 修：`key()` 改成 `KeyStore.getInstance("AndroidKeyStore").load(null)` → `getEntry(ALIAS, null)`，
  **只在缺失时才 generateKey**；加 `synchronized` 防首次并发双生成。
- 附带：`encrypt`/`decrypt` 的 `catch (Exception ignored)` 改为打印到 ABTERM —— 异常静默吞掉正是这类问题反复查不出的原因（同第四十四轮 `TerminalSession.write` 的教训）。
- **旧密文救不回**（密钥已换过多次，Keystore 里只剩最后一把）：用户需在编辑框重输一次密码；
  为此把编辑框的提示改成「已存密码已失效，请重新输入一次」（原来误导性地显示「留空保持原密码不变」）。

### 第三个问题：键盘把对话框按钮整个盖住

### 第四十五轮·收尾精修 + 补跑回归（commit 238cf68）
- **weight 不能一刀切**：上轮为防 Row 溢出给同一行**两个** Text 都加了 `weight(1f)` → 两条平分剩余宽度，
  反而把长的挤成两行（MainActivity「并发探测（推荐）」实测 53px→106px，整体还右移）。
  正解：**只给较长的那条加 `weight(1f, fill = false)`** —— 短文案按固有宽度排（布局与改动前逐像素一致），
  长文案放不下时最多被压到分配宽度内换行，仍不会撑爆整行。「密码 / 密钥」两条都短 → 直接回退成无 weight。
  根因细节：`Modifier.weight` 默认 `fill = true` 会**强制占满分配宽度**；同一行多个 weight 会平分宽度。
- **补跑上轮欠的回归**（改过但没实机跑过的地方）：
  1. MainActivity 编辑服务端对话框：`imePadding + DialogProperties(decorFitsSystemWindows=false)` **无副作用**
     （标题 y=176 未顶状态栏、底部三键都在屏内）；探测行恢复单行。
  2. 服务器编辑框：协议两行紧凑；认证方式「密码/密钥」回到 x=344/561，**与最初 dump 逐像素一致**。
  3. **终端页应急密码框**（上轮新增复选框 + 落盘路径，没跑过）：键盘弹出时「连接」在 y=1017
     （键盘顶约 1433）可点；点连接后 `passwordEnc` 落盘，日志
     `needsManualPassword 认证=password 手输过=true 密文=48B 可解=true -> false` ✓ 完整闭环。
- 交付包 md5 更新为 **7c47ca9f**（旧 f31fc8a1）。
