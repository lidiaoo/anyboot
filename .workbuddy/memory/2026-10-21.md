## SOL 面板：Windows「服务未注册」误判修复 + UI 调整

根因：`sol_status_snapshot()` 的 Windows 分支只认 `schtasks /Query /TN sol` 退出码 0。
任务是 `/RU SYSTEM /RL HIGHEST` 建的，任务文件 ACL 只给 SYSTEM/Administrators，非管理员
query 回「拒绝访问」、`Get-ScheduledTask` 枚举直接跳过它（install.ps1 的 Task-State 注释
写了同一件事）→ 界面永远「服务未注册」。另外 `sol_process_alive()` 与端口探测的 PID 都用
`pgrep -x sol`，Windows 没有 pgrep → 进程兜底恒 false、netstat 段是死代码。

改动（src-tauri/src/sol_panel.rs）：
- 新增 `sol_process_pids()`：Windows `tasklist /FI "IMAGENAME eq sol.exe" /FO CSV /NH`，Unix `pgrep -x`。
- `sol_listening_ports()` 改用 pids；Linux 匹配 `pid=<pid>,`。
- 新增 `parse_ledger_service()`（纯函数，带单测）：`incomplete=false` + `created_unit=true` +
  `kind` 匹配 + `name=sol`；`sol_service_from_ledger()` 读 `~/sol/install.json`。
- Windows：schtasks 成功以其为准；失败则台账认注册、`service_active = 进程在跑`。
- Linux：注册判据改 `systemctl show -p LoadState`（`is-active` 会把「已停止」误报成「未注册」）。

前端（ui/index.html + app.js + styles.css）：
- 「一键安装（调终端）」→「手动安装（调终端）」，已解压则直接 `sol_install_terminal`，不再重复下载。
- 删除包区「安装（静默）」「安装（调终端）」两按钮及其 JS。
- Token 设置上下两排：上排当前 token 纯文字（span.sol-token-value）+ 复制；下排输入 + 生成/应用。
  值另存 `solHttpTokenValue`，复制降级改离屏 textarea。

## 服务重启三端重写（sol_service_ctl）

原实现 `cfg!(target_os="macos")` 二分，else 全给 systemctl → **Windows 上必失败**
（没有 systemctl）；且 macOS 的 stop 用 `launchctl kill`，plist 是 `KeepAlive=true`，
launchd 毫秒级拉回，等于没停（install.sh:166 自己记过这坑）。

改法（src-tauri/src/sol_panel.rs，`sol_service_ctl` 起 ~3432）：
- 命令改 async + `spawn_blocking`（授权框要等人，不能占 tokio 线程）；加 `SolOpGuard`；
  成败都 `record_action`（以前失败不回执）。
- 抽出 `sol_service_ctl_blocking()` 三端分派；`wait_process_state()` 做 PID 级复核
  （**不信退出码**，这是三端共同规矩）。
- Linux：`systemctl <action> sol.service`；失败时把 `Interactive authentication required`
  单独翻译成「没有 polkit 授权代理」并给手动命令（不套 pkexec：同一个 polkit，没用）。
- macOS：start=`kickstart`（失败退回 `bootstrap system <plist>`）、restart=`kickstart -k`、
  **stop=`bootout`**（真停）。osascript 套 administrator privileges，-128/取消单独识别。
- Windows：整段塞进**同一个**提权 PowerShell（`Start-Process -Verb RunAs -Wait -EncodedCommand`），
  结果经临时文件回传（无 BOM UTF-8）。四分支矩阵：任务 missing→no-task；Ready 但有进程→
  manual-process（不许起第二个，否则撞端口）；Running→`schtasks /End`→轮询 5s 退出→
  `/Run`（失败重试 3 次）→轮询 8s 起来；只有拿到新 PID 才判 ok。
- 前端 `ui/app.js` 重启按钮：`call()` 失败会返回 undefined，原来的 `message || "已重启"`
  会把错误盖成假成功 → 改成只在有 message 时显示。

验证：`cargo check` ✅（0 error，7 个告警全是历史遗留）；`sync_commands_never_block` ✅、
`ledger_service_*` ✅；`node --check ui/app.js` ✅（行尾仍全 CRLF）；内嵌 PowerShell 脚本
用 Parser 解析 0 错误。

## 「手动安装（调终端）」点了只有蓝窗口一闪而过

现象：点按钮后看到一个蓝色 PowerShell 窗口闪一下（约 9 秒），没有可交互的安装窗口；
但 `install.log` / `elevated-install.progress` 显示安装其实**成功了**（10:59:31→10:59:39）。

根因（实测确认）：`spawn_terminal` 用的是 `crate::command("cmd")`，而它在 Windows 上
一律给子进程带 `CREATE_NO_WINDOW`（lib.rs:87-99）。于是 `cmd /C start "" cmd /K ...`
拉起的窗口被"隐藏"吞掉，用户唯一能看见的就是 `install.ps1` 自己 `Start-Process -Verb RunAs`
提权重跑时开的那个 PowerShell —— 它跑完自行关闭（官方脚本就是这么设计的），所以"一闪而过"。

探针实测（python + `IsWindowVisible`）：
- `CREATE_NEW_CONSOLE` → 窗口存在且 `IsWindowVisible=True`，标题可读；
- `CREATE_NO_WINDOW` → `EnumWindows` 连窗口都枚举不到。

修法（`sol_panel.rs::spawn_terminal` 的 windows 分支整段重写）：
1. 不再走 `crate::command`，改用裸 `std::process::Command` + 显式 `CREATE_NEW_CONSOLE`；
2. 不再拼 `cmd /C start "" cmd /K "cd /d ... && script"`（嵌套引号会被 cmd 剥错层），
   改为直接起 `powershell -NoProfile -NoLogo -ExecutionPolicy Bypass -NoExit -Command <script>`；
   路径一律用**单引号字面量**（`ps_quote()`，只转义 `''`），空格/中文/$ 都安全；
3. `-NoExit` 是关键：脚本退出后窗口停在提示符，最后一行打印退出码，不会一闪就关。
   实测参数解析：中文标题、`Set-Location -LiteralPath 'C:\Users\jianghh'` 全部正确，rc=0。

顺带改了一键安装的提示文案（原来写"菜单选 1"——当 `install.yaml` 存在时脚本按配置直接跑，
根本不弹菜单，且会提权后重跑，文案误导）。

## 一键安装（静默）：日志看不到 + 计划任务没注册

用户反馈：点「一键安装（静默）」后计划任务没运行，日志区也没有任何安装过程。

### 根因 1：日志根本没推

`run_windows_installer` 用 `wait_with_output()` 一次性收输出，只有整段结束后才
`sol_log` 一行「静默安装完成」。中间几十秒到几分钟用户什么都看不到；失败时直接
`Err` 返回，日志区连一行都没有。

修法：改成**流式逐行**推 `sol_log`（`stream_utf8_lines`），失败也补一行 `✗ 静默安装失败`，
装完再打一条服务状态快照（installed/loaded/active/process/ports）+ 没跑时的下一步提示。

### 根因 2（更严重）：静默安装从来没有管理员权限

原来的调用是「设 `SOL_INSTALL_ACTION=install` 环境变量 + 关 stdin」。
但 `install.ps1:1240` 只要看到这个变量就认为自己是「UAC 升权后的子进程」，
**直接跳过 `Escalate-IfNeeded`** —— 于是 `schtasks` 注册/启动计划任务、改 PATH、
防火墙这些 `[admin]` 步骤全被跳过，脚本还 `exit 0`。

现场特征（一眼认出来）：`~/sol/install.log` 里只有 `[user]` 几行，
**没有 `[admin] 注册并启动计划任务`**；界面提示「装完了」，但 `Get-Process sol` 为空、
UDP 10/11/12 没监听。

修法：**不设 `SOL_INSTALL_ACTION`**，改成用 stdin 喂菜单答案（安装 `1\ny\ny\ny\n`，
卸载 `2\nn\ny\n`）+ `SOL_INSTALL_NO_OPEN=1`。脚本走完整菜单 → 自己弹一次 UAC →
以管理员身份装完。实测输出里有 `（已用管理员权限重跑：install）` / `执行的动作 install（服务 True）`。

`$Piped` 只在 `irm | iex`（`$PSCommandPath` 为空）时为真，走 `-File` 不受影响。

### 编码坑：`cmd /U` 的输出是混合编码，怎么解都乱

一开始用 `cmd /U /C install.cmd` + 按 UTF-16LE 解码，输出是 `쯔탐쏖†렠뗄펽믃` 这种乱码。
原因：**`/U` 只让 cmd 自己写 UTF-16，被它调起来的 powershell.exe 仍按控制台代码页（936）
写 GBK**，两段混在同一条管道里，按任何一种编码解都会毁掉另一半。

修法：去掉 `/U`，改 `chcp 65001 >nul && <install.cmd>`，整条链统一 UTF-8，按字节找 `\n`
切行（UTF-8 的 `\n` 单字节，多字节字符续字节都 ≥ 0x80，不会切坏）。单测
`utf8_install_output_streams_line_by_line` 用「每次只读 1 字节」验证跨块中文。
