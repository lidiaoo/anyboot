## 真根因：白底来自 wry transparent feature 没开（macos-private-api）

## 修复：dock 瞬间主界面内容在热区缝里残留一拍
- 现象：透明修好后，停靠瞬间主界面在缝里残留一角再消失。

## 修复（二轮）：dock 残影仍在 —— 窗口服务器缓存旧帧
- 上轮媒体查询只管「新绘的帧」；macOS 窗口服务器在窗口 hide→show 重新出现的第一帧，先摆出**隐藏前缓存的最后一帧**（WebView 旧画面=主界面切片），新帧下一拍才到 → 残影仍在。
- 修法：dock 在窗口**还可见**时 eval 给 html 加 `dock-pending` 类（CSS：main/.app-columns/.status-bar 藏掉 + html/body 透明），sleep 80ms 让 WebView 真把这帧刷出去，再 hide→缩→show。缓存帧=全透明 → show 无旧内容可闪。原生背景也透明，这 80ms 里全尺寸窗口在屏幕上等于不存在（用户只看到「窗口消失→白条出现」）。
- undock show 前 eval 移除 `dock-pending`（show 后第一帧旧缓存本来就是近全透明白条缝，拉伸无内容）。
- 安全性：dock 由 watcher 线程自调（sleep 不自竞争）；`mark_geometry_busy` 在 sleep 前已立，docked 分支遇 busy Hold。command 线程调 dock（热区滑条重贴）时光标在设置界面非贴边，不会误触发 undock。

## UUID 键空间研究 + macOS FAT 识别修复（实证驱动）
- **UUID 写法三套键空间**：① FAT 卷序列号（引导扇区 FAT32 偏移 67 / FAT12/16 偏移 39，4 字节 LE）→ GRUB fs-uuid / blkid 写作 8 位 hex（E537-7F31，blkid 按 "%04X-%04X" of (serial>>16, serial&0xFFFF)）；② macOS diskutil 的 Volume UUID：msdosfs 挂载时现算 MD5(kFSUUIDNamespace b3e20f39-f292-11d6-97a4-00306543ecac ‖ 序列号 4B LE ‖ BPB 总扇区数 4B LE) 再打 v3+变体位（msdos.util(8) 手册 + whichdisk crate 文档）；③ GPT 分区 UUID（DiskUUID，与文件系统无关）。② 不可逆（MD5 + 扇区数参与哈希）。
- **实证方法**：hdiutil create 64MiB UDRW 镜像（普通文件，引导扇区免 root 可读）→ 读序列号 89281502 / BPB 131070 → 挂载后 diskutil 报 C713F818-031B-32F2-8BB7-F475F8DACC5D，Python 正向 MD5 算出的值完全一致。关键细节：BPB 总扇区 131070 < 分区 131072（newfs_msdos 对齐吃 2 个）→ 正向匹配要往下试一段（实现取 256）。
- **修**：① macOS esp_probe 提示重写（说清为何取不到 + Linux/Windows 哪里读）；② grub_esp_dir/esp_mount 原来拿 8 位 digits 比 36 位 Volume UUID（永远命不中）→ 新 apple_volume_matches：8 位正向派生（DiskInfo 新增 disk_size 解析 Disk Size 行，扇区候选=大小/bps∈{512,1024,2048,4096} 各往下试 256）、32 位直接比；③ Linux esp_probe 的 fat 判定 starts_with("FAT") 漏 vfat（V 开头）→ matches! 补 VFAT/MSDOS/FAT/FAT12/FAT16。
- **Linux fat32 vs vfat 结论**：内核 fs 类型就叫 vfat（fat32 只是 mount -t/fstab 的别名），blkid/lsblk/findmnt/udev 一律报 vfat；GRUB insmod fat 通吃 FAT12/16/32。FAT_FILESYSTEMS 常量已含两者。
- 新依赖 md-5（只为复现 Apple 派生，非通用哈希用途）。3 个新单测（92 全过）。

## 23:10 「打开 Web 页面」点了没反应 → 改用 ShellExecuteW

  Win32_UI_Shell / Win32_UI_WindowsAndMessaging），即发即返回；返回值 ≤32 判失败并回报错误码。

## 23:17 修「token 打一半就被刷新」：轮询 401 把输入框清空
- 根因：网页端 2s 轮询 `/api/ui-state` 带空/旧 token → 401 → `requestRemoteToken()`

  ② `requestRemoteToken` 在输入框已开时只更新文案、不重开不清空；③ 轮询开头 `if (!remoteToken) return;`
  （没 token 时不再产生 401 洪流，也让 140 那种旧 token 客户端安静下来）；④ 点过「暂不连接」置
