## 发布 v0.2.1（0.2.0 → 修订号 +1）

用户选择「小版本」= 修订号 +1（v0.2.1），不是次版本 0.3.0。

- 版本号七处同轴：`Cargo.toml` / `Cargo.lock`(anyboot) / `tauri.conf.json` / `package.json` / `package-lock.json`(根+packages[""]) / `build.gradle.kts`(versionCode 201) / `Info.plist` + `project.yml`(CFBundleVersion 201) / README badge。
- **坑：iOS 的版本号有两处**——`Info.plist` 与 `project.yml`（xcodegen 的源头）。只改 plist 会被 `xcodegen generate` 覆盖回旧值。
- 流程：先等 `workflow_dispatch` 的手动 run（41219644967，5 job 全 success）确认 main 可构建 → 改版本号提交 6b5666b → 推 main → 打 tag v0.2.1 → tag 触发 build-all（version-check 过闸 → 5 平台构建 → release job 自动建 release 并传 8 资产 + SHA256SUMS）。

### release job 第一次挂：merge-multiple 保留子目录
- 现象：`ls: cannot access 'artifacts/*setup*.exe'` → `cp: cannot stat ''` → exit 1，release 没建出来（构建全成功，纯工作流 bug）。
- 根因：`actions/download-artifact@v4` 的 `merge-multiple` 按**产物 zip 内部相对路径**落地。desktop-macos 只匹配 `dmg/*.dmg` 一个目录 → 文件落在 `artifacts/` 根；desktop-windows 同时匹配 `nsis/` 与 `msi/` → LCA 是 `bundle/`，解出来是 `artifacts/nsis/*.exe`、`artifacts/msi/*.msi`。
- 修法（fe4d584）：命名步骤全部改用 `find artifacts -type f -iname <pattern>` 递归取第一个，找不到就打印 artifacts 实际内容再退 1。本地用模拟目录结构（nsis/msi/deb/rpm/appimage 子目录 + 根目录 dmg/apk/ipa）验证通过。
- 重跑方式：**tag 必须重指**——`gh run rerun` 用的是该 run 自身 SHA 的工作流文件，改 main 不生效。做法：`git tag -d v0.2.1` → 在新提交上重打 → `git push origin v0.2.1 --force`（此时还没有 release，无副作用）。
