## 发布 v0.2.1（0.2.0 → 修订号 +1）

用户选择「小版本」= 修订号 +1（v0.2.1），不是次版本 0.3.0。

- 版本号七处同轴：`Cargo.toml` / `Cargo.lock`(anyboot) / `tauri.conf.json` / `package.json` / `package-lock.json`(根+packages[""]) / `build.gradle.kts`(versionCode 201) / `Info.plist` + `project.yml`(CFBundleVersion 201) / README badge。
- **坑：iOS 的版本号有两处**——`Info.plist` 与 `project.yml`（xcodegen 的源头）。只改 plist 会被 `xcodegen generate` 覆盖回旧值。
- 流程：先等 `workflow_dispatch` 的手动 run（41219644967，5 job 全 success）确认 main 可构建 → 改版本号提交 6b5666b → 推 main → 打 tag v0.2.1 → tag 触发 build-all（version-check 过闸 → 5 平台构建 → release job 自动建 release 并传 8 资产 + SHA256SUMS）。

### release job 第一次挂：merge-multiple 保留子目录
- 现象：`ls: cannot access 'artifacts/*setup*.exe'` → `cp: cannot stat ''` → exit 1，release 没建出来（构建全成功，纯工作流 bug）。
- 根因：`actions/download-artifact@v4` 的 `merge-multiple` 按**产物 zip 内部相对路径**落地。desktop-macos 只匹配 `dmg/*.dmg` 一个目录 → 文件落在 `artifacts/` 根；desktop-windows 同时匹配 `nsis/` 与 `msi/` → LCA 是 `bundle/`，解出来是 `artifacts/nsis/*.exe`、`artifacts/msi/*.msi`。
- 修法（fe4d584）：命名步骤全部改用 `find artifacts -type f -iname <pattern>` 递归取第一个，找不到就打印 artifacts 实际内容再退 1。本地用模拟目录结构（nsis/msi/deb/rpm/appimage 子目录 + 根目录 dmg/apk/ipa）验证通过。
- 重跑方式：**tag 必须重指**——`gh run rerun` 用的是该 run 自身 SHA 的工作流文件，改 main 不生效。做法：`git tag -d v0.2.1` → 在新提交上重打 → `git push origin v0.2.1 --force`（此时还没有 release，无副作用）。

## 关于页三端同构（0a0be40）

用户口径：「pc 和移动端的关于要保持一致 不能有区别，不要影响文字展示，考虑自适应 flex 布局」。定案两个点：更新详情**点开才展开**（不常驻第四张卡）、文案**以移动端为准**（标题 AnyBoot，不是 AnyBoot Remote）。

- 统一结构（三端逐字一致）：版本卡（logo 64/圆角 24/accent 15%）→ 更新详情（`#update-section` 带 `.hidden` 起始收起）→ GitHub 卡（仓库行 + ★ 徽标 + Star/Fork/Issues + 引导语）→ 链接卡（更新日志 / 问题反馈 / 开源许可 MIT）→ 署名 `Made with AnyBoot · 2026`。
- 简介统一为：`多系统一键切换 · GRUB 管理 · 远程电源控制 · SSH 跳板机隧道 · SFTP 文件传输`；Android 标题由 AnyBoot Remote 改 AnyBoot，Android/iOS 描述各补 SFTP。
- 展开入口：版本卡「检查更新 ›」胶囊 → `revealUpdate(true)`（展开 + 立即查一次）；托盘进入走同一函数。远程网页 `HAS_TAURI=false` 时更新详情与胶囊一起 remove，不留死按钮。
- PC 拉仓库数据：`fetch` → api.github.com，6s AbortController 超时，失败读 `localStorage['anyboot.github.stats']`，再失败显示「…」（与移动端 github_cache 同口径）。
- `hub_about_open` 白名单从 {repo, releases} 扩到 {repo, releases, issues, license}。
- **flex 排版的坑**：`.about-wrap` 要显式 `min-width:0`，否则父级是 flex 行容器时卡片按 min-content 撑出窗口、文字被右侧裁掉（截图排查时一度以为样式写错，实际是预览壳少了 `.content` 这一层）。
- 窄屏验证手法：Chrome headless **最小窗口 500px**（`--window-size=300` 实际仍是 500，截图会裁边，别被误导）；要模拟更窄就把页面塞进 `width=320/380` 的 iframe，媒体查询才按 iframe 视口生效。
- 构建：cargo 501 测试全绿；Android assembleDebug 通过；iOS `xcodebuild ... generic/platform=iOS Simulator` BUILD SUCCEEDED。
- **dev-reinstall.sh 的 JDK 探测修了两次**：先按 glob 取到 Java 8（AGP 要 ≥11），改「取第一个 ≥17」又拿到 Java 25（AGP 8.7 只到 21，报错就是一句 `What went wrong: 25.0.4`）。最终按主版本 **17..23** 区间挑，本机落到 `~/Library/Java/JavaVirtualMachines/jbr-21.0.11`。
