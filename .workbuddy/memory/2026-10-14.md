## 停靠态重置位置要点两次（ae24ee3）
- 根因：`center_main_window` 不处理 `auto_hide_docked`——白条态读数=白条尺寸，居中落点是「白条的居中点」；真正的展开靠 Moved 事件「拖离停靠位」分支顺手做掉 → 第一次点=展开在偏位上（偏出正中半个窗口），第二次才在完整尺寸上居中。
- 修法：`center_main_window` 顶部 docked 时先 `undock_main_window`（完整展开链路：装饰/尺寸/置顶）→ **清 `auto_hide_reanchor`**（undock 武装的重锚瞄准停靠位，留着会把窗口拽回边缘跟居中打架）→ `MAIN_SIZE_PENDING=true`（读数停在白条尺寸，先用设置里记的尺寸算居中，centering_size 既有机制）。
- 定则：居中一条白条没有意义；「展开+落位」二段式路径里，前一段武装的重锚计划必须在终点落位前清掉。`pending_enter` 只属于托盘呼出语义（不进则回藏），重置路径不挂。
- 单测 111：`centering_after_undock_ignores_the_strip_reading`（白条读数 40x1080 × requested 932x720 × pending → 用请求值）。

## 居中系统性落偏：读数是逻辑值（三连修，本轮根治）

## 白条位置真因（本轮定案，c536d5d）：锁定窗口大小 = set_resizable(false) 钉死尺寸
- 取证闭环（用户 12:20 那轮日志 + 本机复现台）：
  - 日志：`dock begin edge=Right target=(3752,274)`（请求 client=80x1440 物理）→ `dock done outer=400x1504 client_size=400x1440`；前端 `strip rect css=(194,0 6x720) viewport=200x720 dpr=2`。即窗口实际 200 逻辑px 宽 → 白条画在该窗口右缘 = 物理 4140..4152，越过 A 右边界 3840 → 落在屏 B 上 300px 处。**根本不是「缩放的账」**：外框比客户区高 64 物理px（=32 逻辑标题栏）、dpr=2 都自洽，只有宽度被夹在 200 逻辑px。
  - 复现台（Xvfb 3840x2160 + `GDK_SCALE=2` + `mutter` + 跑**真机 app 本尊**，配置走 `XDG_CONFIG_HOME` 副本抄用户 settings.json）：贴顶请求 1864x80 物理 → 实测 1864x400；`xprop WM_NORMAL_HINTS` = `min 1864x400 / max 1864x400`（GDK 把「不可缩放」写成 min==max==当前尺寸）。
  - 裸 GTK 探针（probe.py..probe5.py）：4 种 WM（kwin_x11/xfwm4/mutter/muffin）× 2x 缩放下窗口都能缩到 40x720 —— **所以不是 GTK/WM/页面 min-width 的锅**；但只要 `set_resizable(False)`，窗口立刻跳到 **200x200 逻辑px** 且之后 `resize()` 全被忽略（WebKitWebView 子控件最小尺寸 ≈200x200）。用户的 `windowSizeLocked=true` 走 `apply_window_size_lock` → `set_resizable(false)` → 必现。
- 修法（3 处）：`dock_main_window` 在 set_size 前 `set_resizable(true)`（贴边期间临时解锁）；`undock_main_window`（show 之后）与 `restore_main_dock_size`（用户抓白条拖离）调用 `apply_window_size_lock(app)` 重新上锁。**回锁必须在几何请求之后**——回锁自带夹取（请求被夹进 [200, max]），放前面会把尺寸夹回 40px。
- 复现台端到端对照（mutter/2x）：修前右缘 `client=400x1440`（白条 4140 = 屏 B）；修后 `client=80x1440` @3752（白条 3820..3832 = A 右边界内 4 逻辑px ✓），展开后 `min=max=1864x1440` 锁仍在 ✓。单测 112 全过。
- 定则：**GTK3 下 `set_resizable(false)` 会把窗口尺寸钉在「子控件最小尺寸」上（WebKitWebView ≈200x200 逻辑px），之后 set_size 被夹进 [子控件最小, 几何提示 max]**。任何要缩到 200px 以下的路径（贴边细缝、条形提示）都必须先临时 `set_resizable(true)`，落定后回锁。
- 复现台脚本（本机）：`~/.cache/ab-dock-min/`（probe2-5.py、run-probe*.sh、`run-app.sh` 贴顶、`run-app-right.sh` 贴右缘）。同一套已收进 skill `linux-x11-window-repro`（scripts/gtk-resizable-size-probe.py、repro-real-app-right-edge.sh），SKILL.md 新增两节：「set_resizable(false) 钉死尺寸」「跑真机本尊：设置参数化的差异别用裸探针」。
- 教训：**设置参数化的行为差异，裸探针会全绿**——必须把用户 settings.json 抄进沙箱跑真机本尊；dpr/缩放这类「看起来很可疑」的量要先跟日志对齐（本轮 dpr=2、标题栏 64 物理px 全自洽，真凶是尺寸夹取）。
