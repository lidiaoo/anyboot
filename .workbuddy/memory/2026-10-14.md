## 第二十轮：build:linux 打包链路修复（2026-10-14 晨）
- 用户报 `NO_STRIP=1 npm run build:linux` 在 appimage 环节 `failed to run linuxdeploy`。排障链：
  1) linuxdeploy 本体没问题（--appimage-extract 后直跑正常，版本 1-alpha 659c9db）；
  2) 真根因①：**/dev/fuse 不存在且 mknod Operation not permitted（容器无 CAP_MKNOD）**——AppImage 自挂载必死，modprobe 静默无操作（fuse 可能内建）；
  3) APPIMAGE_EXTRACT_AND_RUN=1 可绕挂载，但解压默认落 /tmp 而本机 **/tmp 是 10M tmpfs** → Exec format error（noexec/空间双坑），换 TMPDIR 指大盘后 linuxdeploy 能跑；
  4) 能跑后挂在 gtk 插件：**容器 userns 下 chown 被拒（chown 1000:1000 → Invalid argument）**，linuxdeploy-plugin-gtk.sh 是 `set -e` + `cp --archive`（保属主失败→cp 非零→插件退）。此路在这台容器彻底走不通。
- 修法（package.json）：`build:linux` → `tauri build --bundles deb,rpm`；`build:linux-portable` → `tauri build --no-bundle && bash scripts/make-appimage-jammy.sh`（脚本素材来自 ~/.cache/ab-appimage 缓存的 orig-backup，不需要现打原版 AppImage；--no-bundle 只出本体）。README 同步三处（平台构建注释/portable 描述/排障节重写）。
- 又一个坑：deb/rpm 打包临时文件也吃 /tmp，10M tmpfs 直接 `No space left on device (os error 28)`——**本机打包一律 `TMPDIR=/home/jianghh/.cache/ab-tmp`**（mkdir -p 先建）。
- 验证：`npm run build:linux` 出 deb+rpm ✓；`npm run build:linux-portable` 全链 ✓（jammy md5 f9703a2236d485b56b1177e8dcd28a58，含自动 zig 重链与三道终验）。
- 教训：**"failed to run linuxdeploy" 在容器里优先查 /dev/fuse 与 chown 能力**，NO_STRIP 只治 strip 一类；AppImage 工具链（linuxdeploy/appimagetool）在受限容器不可修，绕行=不用它。
