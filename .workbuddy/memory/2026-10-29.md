# 2026-10-29

## Windows 侧 ext4 直读接通（grub「自动读取」通道）

`linux_grub::probe_raw` 在 Windows 原来是 `Err("…还在做…")` 占位，现在真实现了。

改动三处：
- `channels/partitions.rs`：新增 `LINUX_GPT`（`0fc63daf-8483-4772-8e79-3d69d8477de4`）+ `Partition::is_linux()`，
  复用现成分区表缓存（已带 `offset`）。
- `channels/ext4_raw.rs`：新增 `#[cfg(windows)] FileSource::open_physical(disk, base, writable)`，
  打开 `\\.\PhysicalDriveN`、`base` = 分区起始偏移。`FileSource{base}` 本来就支持偏移读
  （`read_at` 就是 `pread(base + offset)`），这里只是补一个构造函数。
- `channels/linux_grub.rs`：把 macOS 里那 90 行「逐分区解析」抽成
  `scan_ext4(&mut Ext4, &Ext4Candidate)` 两端共用；Windows `probe_raw` 遍历
  `partitions::all()` 的 Linux 分区、按 offset 打开、调同一个 scan；`write_env_block`
  补 Windows 版（`disk1p3` → 反查 offset → 整盘读写）；`parts_for_sim` 的 Windows 分支
  从「恒返回不支持」改成读 `linux_probe_cache`。

关键事实（下次别重复踩）：
- **`probe_raw` 在 Windows 天生就在提权进程里跑**：`probe()` 非 Linux 一律走
  `probe_via_elevated`，物理磁盘 `CreateFile` 本来也要管理员，所以这里不用自己判断权限。
- 偏移来自 `Get-Partition` 的 `Offset`，**不需要 `DeviceIoControl`**（原方案里这句是多余的）。
- `PartReport.dev` 既有约定是 `disk{d}p{p}`（macOS `disk0s9` / Linux `sdb1`）。写路径靠
  `parse_win_dev` 反解，**认不出就报错，绝不猜偏移**。
- 写时**不复用**父进程的分区表缓存，重新查一次：写错偏移会写坏别人的分区。
- 自动扫描（`allow_fallback=false`）在 Windows 不弹 UAC，所以模拟扫描拿不到 Linux 内核清单，
  要用户点一次「重新读取」；提示语已改成这个意思，不再是「这一端不支持」。
- **未验证（到期更正）**：上一轮记「开发机没有 ext4 分区」是旧状态 —— 现在本机有
  **10 块** `0fc63daf` 分区（见下一节实测数据）。但 `\\.\PhysicalDrive0` 非管理员
  一律 `PermissionError`，所以真机路径仍要靠点「重新读取」弹 UAC 才能跑。

## 「没定位到你选的 ESP 对应的 Linux 分区」的根因（同日）

症状：Windows 上点「重新读取」能扫出 ext4 分区，但候选列表里一块都不中，落在
「没定位到你选的 ESP 对应的 Linux 分区：从下面的列表里选一块」。

根因：Windows 版 `probe_raw` 构造 ESP 身份时把 `fs_uuid`/`label` 留成了 `None`，只填了
`part_uuid`。而 `locate()` 认「哪块 Linux 分区挂的是这个 ESP」靠的是 fstab 里
`UUID=E537-7F31 /boot/efi vfat` —— **那个 UUID 是 FAT 卷序列，不是分区 GUID**。
没有它就永远只能按 PARTUUID 匹配（fstab 里几乎不这么写），于是 exact 恒不中。

修法（对齐 macOS）：
- 读 ESP 首扇区拿身份：Windows 走 `FileSource::open_physical(disk, offset, false)`，
  macOS 走 `/dev/rdiskNsM`，读 512 字节后**共用** `esp::fat_boot_sector`。
- **别自己固定读 0x43**：FAT12/16 的序列号在 `0x27`、卷标在 `0x2B`，FAT32 才是
  `0x43`/`0x47`。簇数判类型（<4085 FAT12 / <65525 FAT16 / 否则 FAT32）这件事
  `esp::fat_boot_sector` 已经做好了，`fat_volume_serial` / `fat_volume_label` 都改成委托它。
- 卷标全空格必须返回 `None`：空串会被 `LABEL=` 当成命中，等于随机选一块。
- 枚举口径也放宽到与 macOS 一致：**不筛 GPT 类型**，Linux 类型优先、其余兜底，
  靠 `Ext4::open` 判定；非 Linux 类型打不开不刷问题列表（MSR/恢复分区没有文件系统）。
- 提示语分三档，别再含糊成一句：`没扫到任何 ext4` / `还没认出 ESP` /
  `认出了 ESP 但读不到卷序列与卷标` / `认出了也有钥匙但 fstab 没挂它`。

本机实测数据（开发机，别当通用假设）：10 块 `0fc63daf` Linux 分区；ESP = `H:`，
GUID `b3fbe669-…`，但 **GPT 类型被写成 `ebd0a0a2`（微软基本数据）**，所以
`win_esp::list()` 永远是空表 —— 自动读取不依赖它（按 GUID 认），OC 通道才靠盘符兜底。
`Get-Volume` 和 `fsutil` 在这里都拿不到卷序列（前者 SerialNumber 为 null，后者要管理员），
卷标是 `ARCH-EFI`。
