## 第九轮：主界面加长 + GRUB 列表三种展示方式

用户原话：

经确认：高度加到 **900**；展示方式**两种都做、可切换**（内嵌 / 加宽主窗口 / 独立跟随窗口）。

### 实现

1. **高度 680 → 900**：`tauri.conf.json`，常量 `MAIN_HEIGHT = 900` 与之对齐。

2. **`Settings.grub_list_view: String`**（inline / wide / window，serde default）+
   `normalize_grub_list_view()` 纯函数（不认识的值回落 inline，有单测）。
   经 `SettingsView` 的 `#[serde(flatten)]` 自动带到前端（`settings.grubListView`）。

3. **窗口形态（全部后端负责）**：
   - `apply_grub_list_view(app, mode)`：
     - inline → 主窗口 460×900 + 关闭独立窗口；
     - wide → 主窗口 **920**×900 + 关闭独立窗口；
     - window → 主窗口 460×900 + 开/显示独立窗口。
   - `open_grub_list_window()`：创建 `grub-list` 标签的窗口（440×860、resizable、
     `visible(false)` **先建后摆**——沿用通知窗口「先在默认位置画一帧白底」的教训），
     仅当主窗口可见时才开（托盘态不蹦出来）。
   - `place_grub_list_window()`：吸附到主窗口旁——首选右侧，放不下换左侧，
     再不行贴工作区右缘；纵向对齐主窗口顶边并夹进工作区。全程物理像素。
   - **跟随**：`on_window_event` 里监听主窗口 `Moved` → 重摆独立窗口；
     主窗口 `CloseRequested`（藏托盘）→ 独立窗口跟着藏；`show_main_window()` → 补开。
   - **用户点独立窗口标题栏 ×**：`prevent_close` + 隐藏 + **设置退回 inline** +
     publish_ui（下拉框跟实际状态一致，不销毁窗口，重开便宜）。
   - 启动时（setup 尾部）应用已保存的模式：wide 加宽；window 且非 start_in_tray 才开窗。

4. **前端**：

   - GRUB 区顶部加「列表展示」下拉（#grub-view-mode）；window 模式下内嵌列表隐藏、
     显示一行说明（#grub-window-note），下拉值只在和快照不一致时才写（防打断用户）。
   - `ui/grublist.html/js/css`（新）：独立窗口页面。数据同源——进场
     `invoke("get_ui_state")`，之后监听同一个 `ui-state-changed` 广播（`app.emit`

     主题/不透明度跟随 `settings.theme / opacityPercent`。
   - `styles.css`：`@media (min-width: 700px)` 时 `.grub-list` 铺**两列**、高度放开

## 第九轮补丁：三种展示方式来回切换会失效

用户原话：
> 这三种来回切换会有bug导致切换失效

**根因（事件乱序覆盖）**：`apply_grub_list_view` 切走 window 模式时用的是
`close_grub_list_window()`（`window.close()`）。但 `CloseRequested` 处理器是给
「用户点标题栏 ×」设计的——里面会**把设置强制改回 inline 并 publish_ui**。
Tauri 的关闭流程异步走主线程，这个改写比切换命令自己的 `publish_ui` 晚到：
设置刚存成 wide/window 就被改回 inline 并广播，前端下拉框弹回去、内嵌列表又显示
出来，而主窗口尺寸还是宽的（或独立窗口已开）——来回切几次状态就永久错乱。

**修法**：模式切换一律**只 `hide()` 不 `close()`**（`apply_grub_list_view` 里
`close_grub_list_window` 全部换成 `hide_grub_list_window`，该函数已删除）。
`CloseRequested` 路径现在只剩用户点 ×，语义干净。附带好处：窗口常驻不销毁，
反复切换不用重建 webview。

**验证**：`cargo test --release` 68 passed / 0 failed / 0 warning；
`cargo build --release` 成功（11467264 字节，08:32）；`anyboot.exe.pending-9d1`
残留已清（用户退出了旧实例）。教训：**「程序化关窗」绝不能复用「用户关窗」的
CloseRequested 语义**，要么 hide 要么加标志位区分。

### 1. GRUB 独立窗口
- 创建参数加 `decorations(false) + minimizable/maximizable/closable(false) + shadow(true)`：
  无标题栏 = 没有最小化/关闭按钮、也没有拖动着力点。Alt+F4 仍会被

- grublist.css 给 body 加描边（无边框窗口自己衬成面板）。

### 2. 主窗口贴边自动隐藏
- `Settings.main_auto_hide: bool`（默认关）+ 设置区复选框（#main-auto-hide）+
  `set_main_auto_hide` 命令。开 = 启动守护线程；关 = 立即展开。
- **实现方式**：这个 Tauri 版本的 `WindowEvent` **没有** CursorEntered/CursorLeft
  （编译报 E0599 实锤），改用守护线程每 120ms 轮询 `AppHandle::cursor_position()`：
  - 未停靠 + 光标离窗超 350ms → `dock_main_window`（按 `nearest_edge` 贴最近边，
    露 6px 条）；
  - 已停靠 + 光标压到露出的条上 → `undock_main_window`（推回工作区边缘）。
- 线程用 `static WATCHER_RUNNING: AtomicBool` 防重复；开关关掉时自检退出；
  setup / show_main_window / 勾选时三处都会确保它在跑。
- 贴边状态存 AppState（docked / edge / dock_pos）；贴边时 GRUB 独立窗口跟着藏，
  展开时跟着回。
- 关键细节：dock 里**先写 AppState 再 set_position**——贴边触发的 Moved 靠
  dock_pos（24px 容差）认出是自己的回声，不做位置夹取；用户抓着边条拖跑则视为
  解除停靠，落回正常夹取。

### 3. 主窗口拖到任何地方都完整显示
- Moved 处理（handle_main_moved）里做位置夹取：在**相交面积最大的显示器**的
  工作区内 clamp（`clamp_to_work` 纯函数，跨屏拖动自动落到目标屏，不会拽回去）。
  贴边停靠的那次越界是唯一豁免。窗口大于工作区时钉左上角。

## 第十一轮：最小化后独立窗口丢失 + 选中项顶部横幅

用户原话：
> 我选择了独立窗口但是点了主菜单的最小化之后 再点开主菜单 发现独立窗口没了,,,这三种方式都要在最顶部显示选择的系统是哪个 如果是级联的 父级选择的名字+子级选择的名字 最后一级选择的都要大字而且颜色明显 他的上级小一点的字

### 1. 最小化后独立窗口丢失（根因 + 修法）
- Windows 最小化窗口时把它挪到屏幕外 **(−32000,−32000)** 并触发 Moved ——
  旧代码把这当普通移动处理：`clamp_main_window` 跟最小化打架，
  `place_grub_list_window` 又按这个坐标把独立窗口摆到工作区角落。
- 恢复路径上 `open_grub_list_window` 的 `main.is_visible()` 守卫可能读到
  `show()` 刚派发还没生效的**过期值**，直接 return，独立窗口没被补开。
- 修法（三层）：
  1. `is_minimized_position()`（x/y < −20000）识别最小化态：Moved 里只藏
     独立窗口、立即 return，不夹取不摆位。
  2. `open_grub_list_window(app, force_show: bool)`：托盘呼出 / 恢复 / 失焦回归
     都传 `true`，跳过 is_visible 过期值；只有 setup 托盘启动那次传 `false`。
  3. `Focused(true)` 事件（原来只处理 Focused(false)）也补开独立窗口 ——
     覆盖 alt-tab 恢复这条路径。

### 2. 选中项顶部横幅（三种展示方式共用）
- `grub-list-view.js` 新增 `renderGrubActive(container, grub)`：
  activeSelector（nextEntry ?? savedEntry）找到条目；有 submenu 就先渲染
  **父级名 ›**（11px 灰字），再渲染子级名（17px 加粗 `--link` 主题色）；
  顶层条目只有大字；没选过显示「尚未选择启动项」（未填 uuid 时整条隐藏）。
- 主窗口 `#grub-active`（grub-head 之下，**不受展示方式影响**，window 模式也显示）；
  独立窗口 `#grub-window-active`（header 之下）。两页共用同一渲染器与 CSS。

### 验证
- `cargo test --release` 68 passed / 0 failed / 0 warning；
  `node --check` 三个 JS 全过。
- 新 exe：11469312 字节，09:00。`anyboot.exe.pending-b3e` 被运行实例占用，
  等用户退出后删。

## 回合 18：贴边隐藏五项整改（10:44）
用户五点要求，全部落地：
1. 深度绑定：watcher 每 tick 校验 —— mode=window 且主窗口可见时独立窗口
